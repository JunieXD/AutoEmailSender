# 开发约定

[AGENTS.md](../AGENTS.md) 的原则落到这个项目上的具体做法。能由工具检查的写在 lint 和编译配置里，不在这里重复。

| `crates/check` | 发送前检查：规则和收件域名 |

每个领域一个 crate，依赖只朝一个方向：`app` → `api` → 各领域 → `db`。

## 命令

第一次：装好 Rust、Node 和 pnpm，再装 sqlx 的命令行工具：`cargo install sqlx-cli --no-default-features --features sqlite,sqlx-toml`。

| 命令 | 做什么 |
|---|---|
| `pnpm install` | 装依赖 |
| `cargo xtask seed` | 给开发版填示例数据 |
| `pnpm dev` | 启动开发版，界面改了自动刷新 |
| `pnpm preview` | 在普通浏览器里预览界面，终端打印带令牌的网址 |
| `pnpm check` | 提交前的全部检查：格式、clippy、测试，生成的类型和查询元数据是否最新，界面的类型检查、lint 和测试 |
| `pnpm fmt` | 格式化 Rust 和界面的代码 |
| `pnpm sqlx` | 改了 SQL 或迁移后，重新生成 `.sqlx` 里的查询元数据 |
| `cargo xtask types` | 改了操作或它们的类型后，重新生成 `ui/src/api/types.ts` |
| `cargo xtask bench` | 按[性能预算](data-model.md#性能)的规模测高频查询 |
| `pnpm --dir ui icons` | 从 `docs/icon.svg` 和 `docs/tray.svg` 重新生成应用图标和托盘图标 |
| `pnpm package` | 打包安装包 |

- 开发版的数据在仓库的 `.dev-data` 里，应用标识也单独一个（`crates/app/tauri.dev.conf.json`），和装好的应用互不干扰。
- 查询在编译时检查：编译读 `.sqlx` 里的元数据，不用连数据库。改了 SQL 没重新生成，编译会报错。
- `pnpm check` 检查 `.sqlx` 是否最新时不另外编译：先用迁移重建 `target/sqlx.db`，clippy 那次编译连上它，把所有 target 的查询元数据写进 `target/sqlx-check`，再和 `.sqlx` 比较，缺、多或内容不同都报错（`tools/check-rust.mjs`）。和 SQLx CLI 一样，编译前更新各 target 入口文件的修改时间，让增量编译也重新展开查询宏；平常的开发编译仍然离线。
- 生成的 TypeScript 类型是否最新由 `xtask` 的测试检查，用的是 `cargo test` 已经编译好的测试程序，不用再编译、链接一次 `xtask`。
- 工作区没有文档测试，`pnpm check` 只跑 `--lib --bins --tests`，省得为每个 library 启动一次 rustdoc。
- 界面用 TypeScript 7。typescript-eslint 还不支持它，lint 用 oxlint 和它的类型感知规则。
- 界面的测试用 Vitest，和代码放在一起（`*.test.ts`）；要用 DOM 的在文件开头声明 happy-dom 环境。
- CI 在 macOS 和 Windows 上各跑一遍 `pnpm check`，master 要求两个都通过才能合并。PR 准备好后用 `gh pr merge --auto --squash` 设成自动合并，不用等 CI 跑完。

### 官方账号

- `crates/cloud-api` 默认只依赖 serde，统一 `/v1/` 的 JSON 协议、路径和错误码；桌面端开启可选的 `ts-rs` 特性，从同一份导师库协议生成界面类型。官方服务端按公开仓库提交号引用。服务端的表、验证码和限流细节在私有服务端仓库的 `docs/account.md`。
- `crates/account` 经 `net` 的系统代理和系统证书访问服务器，保留连接池但禁止重定向，避免把凭据转交给别的地址。默认地址在正式构建里是 `https://api.auto-email-sender.cn`，开发构建里是服务端仓库 `cargo xtask dev` 起的 `http://127.0.0.1:8787`，避免试用时在正式服务上建账号；构造客户端时读取环境变量 `AUTOEMAIL_SERVER_URL`，存在时使用该值。
- 邮箱去首尾空白、折叠全角英文字母／数字／`＠`／`．` 后转小写。`cloud_api::normalize_email` 是桌面与服务端的同一份规则；规范化结果也用于密码盐。
- 密码不上传、不保存、不记日志。Argon2id v19，`m = 65,536 KiB`、`t = 3`、`p = 4`，盐为 UTF-8 的 `auto-email-sender:` 加规范化邮箱，输出 32 字节主钥匙；HKDF-SHA256 使用空盐（`None`），分别以 UTF-8 字节 `login`、`backup` 为 info，各输出 32 字节登录钥匙和备份钥匙。登录钥匙以无填充 base64url 上传，备份钥匙只存本机。注册、登录只执行一次 Argon2id，主钥匙和密码随即用 `Zeroizing` 清理，备份钥匙不实现面向界面的序列化或会暴露字节的 `Debug`。上述参数和规范化规则改变时必须迁移。
- 本机 `account` 表最多一行，令牌和备份钥匙的保存、清除规则见[数据模型](data-model.md#云端备份)。`State`（生成的 TypeScript 类型为 `AccountState`）仍是 `loggedOut`、`loggedIn { email }`、`expired { email }`，不带钥匙。`account::state` 只读本机邮箱和令牌是否存在，不连接服务器、不获取账号变更锁，断网时也能显示邮箱。恢复备份清掉令牌，保留邮箱，状态为 `expired`。
- `Client::authenticated` 是官方服务共用的带令牌请求入口。实际访问服务器时发现 `session_expired`，只清掉本次使用的令牌及其备份钥匙，保留邮箱并返回 `SignedOut`，随后读取本机状态得到 `expired`；不自动重放请求。实际清掉令牌后通过 Tokio watch 通知订阅者，桌面宿主转成 `account-changed` 事件，界面收到后重新读取 `getAccount`，覆盖界面、后台导师库同步和失败的 Agent 调用。操作错误码 `signed_out` 保留供调用方区分；旧令牌的响应没有清掉任何记录时不发通知。账号变更在同一个客户端内串行执行，避免旧登录覆盖新状态。
- 操作组“账号”：`getAccount {}`、`sendRegistrationCode { email }`、`registerAccount { email, code, password }`、`loginAccount { email, password }`、`sendPasswordResetCode { email }`、`resetAccountPassword { email, code, password }`、`logoutAccount {}`、`deleteAccount { email, password }`。注册和登录返回 `State`，其余写操作返回 `null`。Agent 注销必须确认，说明使用输入的邮箱和删除效果，不含密码。注销绑定用户确认的邮箱；取得账号变更锁后，按共享规则规范化输入邮箱并核对当前登录账号，不同就拒绝，不访问服务器。
- 重置密码后所有设备会话失效；本机正是该邮箱时立即清令牌和备份钥匙。退出登录只有服务器撤销会话成功或确认会话已失效后才清本机记录，网络失败会明确报错。注销成功只删除本机账号记录，不动导师、邮件等本机数据。错误中文由 `account::Error::message` 统一提供。
- 赞助状态只在服务器上，不存本机。操作组“账号”提供 `getSponsor {}` 返回 `{ sponsorUntil }`（读 `GET /v1/account`），`getSponsorTiers {}` 返回时长、价格（分）和服务器生成的爱发电型号链接，界面用系统浏览器打开；`claimSponsorOrder { orderNumber }` 认领订单，返回新的 `{ sponsorUntil }`。
- `getInvite {}` 读取邀请资格、邀请码、已邀请人数和填写期限；`fillInvite { code }` 返回 `{ sponsorUntil }`，`redeemCode { code }` 返回 `{ days, sponsorUntil }`。桌面和服务端共用 `cloud_api::normalize_code` 规范化邀请码和兑换码。上述操作都经 `Client::authenticated`，Agent 调用不用确认。

### 导师库

- `crates/library` 通过 `account::Client::authenticated` 访问官方接口，复用令牌失效处理和错误中文。浏览与预览不取邮箱；一页摘要只做一次本机标记查询，以导师库编号确定已添加／回收站，用索引中的规范化姓名和学校确定可能已有。
- 操作组“导师库”：`getLibraryOrgs`、`listLibraryMentors`、`previewLibraryMentor`、`getLibraryQuota`、`previewLibraryAdd`、`addLibraryMentors`、`listLibraryUpdates`、`applyLibraryUpdates`、`libraryUpdateCount`、`syncLibrary`，全部对 Agent 开放。输入输出从操作声明生成；添加和应用更新沿用表格导入的收件地址确认规则。`previewLibraryAdd` 取得完整记录，首次取得会计入当天数量，重复取得不再计数。
- `mentor::intake::Preview` 只含对应、补充、差异和问题行；表格的 `mentor::import::Preview` 在外层增加文件信息，JSON 展平，表格原有界面形状不变。导师库的行编号固定对应所选 `ids` 的位置，重取时记录顺序改变或部分撤下不会把选择移给别的记录；问题行另带姓名。
- `api::libraries::run` 在桌面应用进程已有的 Tokio runtime 中运行，启动时和之后每小时判断：有令牌且从未成功检查或距上次成功检查至少 24 小时才同步。手动 `syncLibrary` 立即检查。`Synchronizer` 的同一把锁覆盖添加的取记录与写入，以及整个同步检查；等待 Agent 用户确认时释放，确认后重新持锁，用同一次取得的记录复核并写入 `add::write`。同步逐条写事务保存导师资料、待处理项和原始记录；一页完成才保存进度，全部完成才保存检查时间。写入失败经 `db::Writes` 重试，网络／服务端失败只记条数和类别，下小时再试。记录资料只在 Rust 中比较；不按 JSON 内的值查询。
- 待处理更新关联导师库记录，以记录、项和职称的单位唯一，合并导师时随记录转移。列出时计算当前值和默认选择，应用时复核用户看到的值，资料已变化则要求刷新；跳过已与新值相同、回收站和已移除单位的职称。`libraryUpdateCount` 按同一口径统计导师数。导师详情提供各条记录的状态和核实时间，任务候选提供退休／离职／去世提醒；同时有多个状态时按去世、离职、退休选一个。
- 列出、计数和应用的可见性复核共用 `current_profiles` 和 `visible`；按导师编号读取姓名、来源网址、研究方向、首邮箱和完整单位列表，不按字段裁剪，不读取论文、备注和标签。计数对可见差异的导师编号去重；应用只加载所选导师。单位对应复用 `mentor::supplement::affiliation_position`；业务规则见[导师库](data-model.md#导师库)，规模和预算见[性能](data-model.md#性能)。
- 账号行保存同步进度和上次检查时间，注册或登录为不同邮箱时一起清零，同一账号重新登录保留。同步写入前在事务中复核账号，避免换账号期间推进新账号的进度。

### 云端备份

行为见[备份](design.md#备份)，本机数据见[数据模型](data-model.md#云端备份)；服务端接口、限流和清理只在私有仓库 `docs/backup.md` 定义。共享协议仍在 `crates/cloud-api`，服务端按提交号引用。

#### 钥匙和格式

- 备份钥匙沿用账号主钥匙，以 HKDF info `backup` 派生；注册、登录和登录钥匙同一次 Argon2id 计算后保存到 `account.backup_key`。旧登录首次使用时输入密码，走现有登录接口确认登录钥匙正确，再保存本机备份钥匙。密码、主钥匙用 `Zeroizing` 清理，钥匙不进界面类型、日志或备份；登录等钥匙变更清掉材料对象映射和比较基准。
- 数据库快照和每份材料分别用 `zstd` 0.14、级别 3 压缩，再加密。单 frame、窗口 2 MiB，不用字典或多线程，关闭 frame checksum，完整性由 AEAD 负责；显式完成压缩后再取大小。PDF、图片、DOCX 通常压不小，可能略增。恢复限制窗口和输出大小，拒绝尾随数据；数据库 2 GiB、单材料 20 MiB、总明文 4 GiB 的边界沿用本地备份。
- 使用 `chacha20poly1305` 0.11（`zeroize`）和 `aead-stream` 0.6（`alloc`）的 XChaCha20-Poly1305 STREAM BE32。头为 `AESCBK` 后接两个零字节（共 8 字节）、版本 `1`、种类（数据库 `1`、材料 `2`、清单 `3`）各 1 字节，加 19 字节安全随机 nonce 前缀，共 29 字节。库附加 32 位大端计数和末块标志，不手写加密或认证。
- 明文按 64 KiB 分块，每条记录是 4 字节大端密文长度及密文（含 16 字节标签）。完整块调用 `encrypt_next`，最后剩余 0–65,535 字节调用 `encrypt_last`，整除也有空末块；非末块长度 65,552，末块 16–65,551，末块后必须 EOF。每块 AAD 为完整头、规范化邮箱 UTF-8 字节长度（`u16` 大端）、邮箱字节及对象编号的原始 16 字节；清单的对象编号固定为 16 个零字节。每次加密生成新前缀；重传成品不改字节。认证失败不交给恢复。加密内部派生与认证属于允许的哈希用途第 3 条，不加内容哈希。
- 对象编号是客户端生成的随机 128 位小写十六进制数。加密清单是 JSON，含应用标识、格式／应用／数据库版本、导出时间、导师数、邮件数、设备编号和名称、数据库对象编号，以及材料的本地整数编号到对象编号的对应；清单只加密、不压缩。映射在清单里，不改材料表。清单和全部对象的实际密文合计不超过 `30 × 1024 × 1024` 字节，界面标 30 MB；原文件大小和本轮流量都不是容量。

#### 上传和变化判断

1. 开启时读云端状态；来自其他电脑的先下载、解密清单，显示时间、人数、邮件数和电脑名称，确认替换后开启。解不开就说明可能重置过密码、开启后旧备份会被替换，不另建一套覆盖授权或比较交换。
2. 沿用本地导出的 `VACUUM INTO`、脱敏和再次 `VACUUM`，清空钥匙及云端状态／映射；新快照与 `cloud-backup/last.db` 逐字节比较。只有字节相同、材料集合相同、云端当前设备编号和提交时间等于本机上次成功记录时才跳过。SQLite 头变化也可能多传一次，接受这个代价；不逐行比较，不用哈希、时间戳或额外版本计数证明没变。
3. 快照压缩、加密为一个新对象；材料有本机映射的复用原对象编号，没有的压缩、加密并生成随机编号。先在本机计算完整份额，超过 30 MB 就失败，给出总量、数据库和最大的 5 个材料的密文大小及文件名，建议先压小大文件。上传通过账号客户端的文件流入口发送，超时 5 分钟，沿用系统代理、TLS 和令牌失效处理；账号变化先停止本轮，不能拿新账号令牌续传旧数据。
4. PUT 对象后 POST 清单和全部引用；收到 `backup_incomplete` 就补传缺的对象再提交。补传仍用同一对象编号，旧成品不在本机时重新压缩、加密并更新映射中的实际大小；材料不变、钥匙未换才允许这样重建。每次补传后重新核算 30 MB。其他电脑的提交可能删掉本机记着的对象，以服务器缺少列表为准，不加会话或回执。提交返回 `committedAt` 后才保存成功时间和快照基准，材料映射只在完整对象上传成功后记下；本机记账失败沿用 `db::Writes`，不报告成功。
5. 网络失败或重启后重新检查并导出，材料映射仍可复用；提交响应丢失允许重做提交，后提交者成为当前。60 MB 暂存限额不足时等无引用对象清理后再试，不删当前备份腾空间；缺对象补传与提交遇到持续竞争时记本次失败，不无限循环。

任务在现有 Tokio runtime 里运行，同一时间只做一次云端备份或恢复；压缩、加密和文件比较放阻塞线程。开启后启动时补查，此后每小时判断距最近成功检查是否满 24 小时，手动立即备份不等调度；失败下次再试并遵守 `Retry-After`。赞助到期停止自动上传，恢复仍可用，续赞助后继续。只向界面返回成功时间、当前用量、失败原因／时间和正在备份或恢复，不做字节进度。

#### 恢复和开发

先下载并解密清单显示预览，用户确认后使用这份清单里的固定对象编号下载数据库和材料，认证、解压；不在确认后另取一份清单。按映射将材料还原为 `materials/<本地编号>`，生成原有 `manifest.json`，组装成与本地导出相同的 zip，直接调用现有 `prepare`／`confirm`，不另写恢复校验或替换流程。目录、材料集合、计数、大小和应用／数据库版本必须相符；缺对象、认证或解压失败就停止，本机数据不动。恢复前自动备份本机、保留最近 3 份、重启替换和重填凭据的要求沿用本地恢复。密码重置后旧备份解不开，需要在仍有数据的电脑重新登录并备份。

开发使用服务端 `cargo xtask dev`、桌面 `.dev-data` 和本机假账号。新增直接依赖为上面的加密／压缩库、`getrandom` 0.4（随机编号和前缀）、`tokio-util` 0.7（文件流）；不增加进程或端口。测试沿用现有假 HTTP、SQLite 和本地恢复夹具，覆盖字节比较、钥匙切换清映射、缺对象补传、30 MB 边界、篡改／截断、恢复中云端替换和失败不动本机；时间由测试控制，不连外网、不加运行器。

### 桌面后台运行

- `crates/app/src/background.rs` 管理 Tauri 自带的托盘和首次关窗的一次性说明对话框，`autostart.rs` 管理系统登录项；后台工作仍由核心运行。
- 开机自启使用官方 `tauri-plugin-autostart`，macOS 使用默认的 LaunchAgent。登录项以应用标识命名，开发版与安装版分开；启动参数 `--autostart` 让主窗口保持隐藏。普通启动、再次启动、恢复备份后的启动和 macOS Dock 图标打开窗口。启动时读取现有登记命令，只在路径或参数改变时重新登记；macOS 的 App Translocation 临时路径不允许登记。Windows 卸载（不是更新）时由 NSIS 钩子 `crates/app/windows/hooks.nsh` 删掉登录项。
- 界面通过 `ui/src/api/app.ts` 的 `autostartEnabled()` 和 `setAutostart(enabled)` 读写系统状态。插件只在 Rust 层使用，不增加界面的插件权限。
- `crates/app/Info.plist` 设置 `NSAppSleepDisabled`，避免 macOS 在窗口隐藏后通过 App Nap 推迟定时发送和收信。

### Agent 本机通道

- `crates/agent` 提供桌面端和命令行共用的通道；`api::agent` 管理认证、连接和开关生命周期。只有桌面端启动监听；浏览器预览能查询开关，在预览里修改时提示使用桌面应用。
- 开关存在 `profile.agent_access`，默认关闭。`getAgentAccess`／`setAgentAccess` 供界面调用，后者输入为 `{ "enabled": boolean }`。开启成功后才保存为开启；关闭时停止接收新请求、同步撤销未回答请求、关闭监听并删除令牌，随即返回，不等执行中的调用；管理任务继续回收旧会话。每次重新开启使用独立的关闭信号，旧调用不阻塞新连接，也不会恢复接收请求。启动时按保存的开关恢复监听，每次开启或重启重新生成令牌。
- macOS 的端点是数据目录里的 `agent/sock`：子目录创建时即为 `0700`，已存在的先改成 `0700`，再绑定套接字，不改进程 umask 或绑定后的文件权限。macOS 路径最多 103 字节，超长时提示缩短数据目录路径。应用已持有数据目录锁，监听前可删除上次留下的套接字。Windows 的管道名独立随机生成，首次创建要求独占该名称，接受连接前保留下一实例，不把令牌放进可枚举的管道名。
- 数据目录里的 `agent/token` 是 JSON，保存 `token`，Windows 还保存 `pipe`。先写临时文件再替换；macOS 文件权限为 `0600`，Windows 子目录和文件继承当前用户数据目录的访问权限。不在日志或命令行输出中显示。认证第一行限 128 字节、5 秒，同时最多 4 个连接处于认证阶段，接受前取得名额，认证结束或断开即归还；已认证连接不占名额。未认证连接不返回数据；后续每行请求最多 28 MiB，以容纳 20 MiB 材料的 Base64 输入。同一连接按顺序请求；读取端最多保留一个未处理帧，超前请求超过容量时断开，避免等待确认时因背压无法发现连接已断开。
- `api::call_agent` 把 Agent 开关、待确认列表和回答操作留给界面；其余操作交给同一个 `api::call`，未知操作由分发器拒绝。`api::agent::confirmation` 在同一个只读事务里按操作、输入和当前数据生成用户看到的说明。用户确认的是这份说明；允许后、执行前用同一个判断函数重算并直接比较整个 `Description`，仍需确认且说明不同则提示“等你确认期间情况变了，请重新发起”，不执行。已不需要确认或说明相同才由分发器校验、执行；重算与执行之间不另加事务，等待执行锁可能使这个间隙变长。不另存表结构快照，也不因说明中没有、与用户决定无关的值变化而拒绝。
- 待确认请求只在内存里，`listAgentRequests {}` 按登记先后返回 `{ id, op, description: { action, targets, letters }, createdAt }`。`action` 只含应用写的操作和计算出的数量；名称、地址、主题等外部文字只放 `targets`／`letters`。`targets` 每个对象一项，保留用户需要核对的完整文字：空保存删除草稿写导师、主题、保存时间（精确到分钟）、逐行列出的附件（文件名和大小）和整份正文（同一分钟内改过正文或换了附件也能分辨）；恢复任务、恢复邮箱及修改尚在暂停的邮箱写对象名称、将发出的封数和导师数、各导师的姓名／收件地址／封数；修改邮箱地址会影响按同一口径统计的已批准邮件时也确认，写出前后地址；删除类写实际丢失数量和对象名称；合并写重复草稿和已取消任务邮件记录的丢弃数量；更换导师邮箱写原邮箱、新邮箱或自动选择和影响封数。导师补充沿用既有地址排序和导入／候选计划，写出收件地址前后值及影响数量。凡列出待发邮件的导师项，逐封写出原定发送时间（精确到分钟）；任务邮件尚未分配时间时写“按任务的发送安排”，排期变化会改变说明。重试还写出本次立即发送或按任务窗口安排，区分原定时间和本次重试的发送安排。文字不截断、不限个数，展示限制由界面处理，复核只比较这份说明。
- `letters` 只用于四种批准操作，顺序与批准输入一致，每封包含 `mentorId`、`mentorName`、`address`、`mailboxId`／`mailboxAddress`、`sendAt`、`subject`、`bodyMd`、附件的材料 ID／文件名／大小和可选的 `previous` 引用原信。确认信件与实际批准共用 `email::select_attachments` 选择附件，同名文件只保留输入顺序里的第一份。只读取构建这些信需要的数据，不读取任务内其他邮件的正文或已渲染内容。`sendAt.kind` 为 `now`、`at`（`at` 是 UTC 毫秒）或 `task`（带 `taskId` 和完整 `schedule`）；任务为立即发送时用 `now`，窗口时刻在批准时随机分配，确认时明确按任务发送安排，不预报随机结果。
- `answerAgentRequest { id, allow, rendered? }` 只供界面调用。允许四种批准操作时，界面用 `letterHtml(letter.bodyMd, style)` 和 `letterText(letter.bodyMd)` 按 `letters` 顺序生成 `rendered: [{ html, text }, …]`。回复和追问的 `previous` 用于预览引用，回传只含新正文的渲染，核心仍按既有规则追加引用和线程头；任务追问同样处理。允许时缺少渲染或数量不符返回输入错误，请求保留，可重新回答；没有待发信的确认、拒绝、超时和作废无需渲染。核心复核通过后才把回传结果替换进批准输入，忽略 Agent 自带的 HTML／纯文本。批准输入的 `html`／`text` 在接口类型里可省略，普通界面直接批准时仍须提供，缺少时由批准入口报错。已作废的回答提示“这个请求已经失效”。
- 登记、回答或撤销时，桌面端发送不带内容的 `agent-requests-changed`；登记时还把主窗口带到前台，系统通知标题为“Agent 请求确认”、正文仅为 `action`。超时从登记起按单调时钟计 5 分钟，连接断开或关闭开关只撤销未回答请求并通知界面。已经允许或无需确认且已经开始执行的操作由宿主做完；关闭开关后停止写回旧连接，结果无法写回时只记不含内容的日志并丢弃结果。日志只记操作名、允许／拒绝／超时／取消和执行成功与否，不记录输入、说明、信件和结果。每次 Agent 调用成功（包括读取）发送不带内容的 `agent-called`，供界面合并刷新。
- 管理任务与连接任务分别存活：接受连接遇到一般连接错误继续接受，资源耗尽等错误记日志并间隔 1 秒重试，期间仍处理开关请求；单个连接任务失败只记录日志。开关查询始终读取数据库，不增加监听失败状态。
- `operations!` 按组声明操作，文档注释第一行是一句话说明，其余行是补充说明；每项操作必须显式声明 `none`（不用确认）、`confirm`（一律确认）或 `confirm_if`（附条件说明），省略标记不能编译；标记只描述已有确认范围，不参与是否执行的判断。目录和描述共用 `call_agent` 的可见性判断，不列出或描述只供界面使用的操作。`describeOperation` 的 TypeScript 声明包含 `Input`、`Output` 别名和它们引用的类型，复用界面类型生成的配置与收集函数。
- `autoemail list` 按组显示操作及确认标记，`autoemail help <操作名>` 显示说明与类型；两者均调用应用查询。`autoemail --help` 和 `--version` 无需连接应用。`autoemail mcp` 使用标准输入输出提供三个 MCP 工具，工具列表固定、操作目录由应用提供；连接策略、错误和进度通知见[总体设计](design.md#桌面端)。
- 应用最多等用户确认 5 分钟；[Claude Code 默认超时](https://code.claude.com/docs/en/mcp#time-limits-on-mcp-tool-calls)足以覆盖，但 `MCP_TOOL_TIMEOUT` 设得比 5 分钟短时会先超时。收到进度后是否重置计时由[客户端选择](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/basic/patterns/cancellation.mdx#timeouts)；[Claude Desktop](https://support.claude.com/en/articles/10949351-getting-started-with-local-mcp-servers-on-claude-desktop) 和 [Cursor](https://cursor.com/docs/context/mcp) 的官方说明未明确工具超时或进度重置保证，不能保证等待满 5 分钟。
- 最简调用为 `autoemail call <操作名> [JSON 输入]`，省略输入时为 `{}`。需要确认时，通道先返回一行 `{ "waiting": { "action": "…" } }` 中间消息；命令行只把 `action` 写到标准错误，不输出对象内容，继续等最终回答。标准输出只有一行最终的原始 JSON，包含 `error` 时退出码非零。开发构建默认用本仓库 `.dev-data`，可用 `AUTOEMAIL_DATA_DIR` 指向独立开发数据目录；正式构建默认用应用标识对应的数据目录。Windows 上命令行写到控制台时交给 Rust 标准输出处理 Unicode，写到管道和文件时是 UTF-8。PowerShell 把命令行的输出交给其他命令、存进变量，或在 7.4 之前用 `>` 写进文件时，按 `[Console]::OutputEncoding` 解码，中文 Windows 默认是 GBK；cmd 和 PowerShell 7.4 起的 `>` 原样写入。所以 Windows 上的 `--help` 提示先把它设为 UTF-8；Codex 运行 PowerShell 命令时已经这样设。
- `pnpm dev` 和 `pnpm package` 加载 `tauri.agent.conf.json`，Tauri 的构建钩子先运行跨平台的 `tools/build-agent.mjs`，按 `TAURI_ENV_TARGET_TRIPLE` 和调试／发布模式编译 CLI，并复制为 `crates/app/binaries/autoemail-<目标平台>[.exe]`，再构建界面。发布工作流使用相同的配置与构建钩子。基础配置不声明 externalBin，使直接运行 Cargo 的类型检查和测试不依赖预先生成的 sidecar。Tauri 将 sidecar 放在应用可执行文件旁，开发版同样放进 target 输出目录。不要单独运行不带配置的 `tauri build` 来制作分发包。
- `api::agent_settings` 提供六个仅界面可用的操作，输入输出包含在生成类型中：`getAgentCli {}`、`installAgentCli {}`、`uninstallAgentCli {}` 返回 `{ state, command, path, location }`。`state.kind` 为 `notInstalled`、`installed`、`oldLocation`（附 `target`）或 `occupied`；`path` 是 CLI 普通绝对路径，`location` 是 macOS 的链接或 Windows 的 PATH 目录。macOS 先尝试无权限操作，确实缺权限或目录才通过 `osascript … with administrator privileges` 请求授权；旧链接用同目录临时链接替换，其他文件不动，授权后再次核对链接归属。Windows 通过系统自带 PowerShell 读写 `HKCU\Environment\Path`，保留原注册表字符串类型和其余项，在 `HKCU\Software\AutoEmailSender\CliPath` 记录自己加入的一项，用 `WM_SETTINGCHANGE` 广播；比较目录时统一扩展前缀、斜杠、尾斜杠和大小写，不修改当前进程或系统级 PATH，已打开的终端需重新打开。卸载时连同标记键一起删除；卸载应用（不是更新）时，NSIS 钩子用同一个脚本做这一步。
- `previewMcpConfig { client }` 的 client 是 `claudeDesktop`、`claudeCode` 或 `cursor`，返回 `{ path, server, exists, commands, writeUnavailable }`；`server` 是包含 `autoemail` 的完整 JSON 服务项。`commands` 是可直接复制到 macOS zsh 或 Windows PowerShell 的命令行字符串数组，其余客户端为空。找不到 Claude Code 时仍返回完整命令，`writeUnavailable` 给出原因，界面显示原因并禁用写入；可写时该字段为 `null`。预览留在当前 Context 的内存中；用户确认后调用 `writeMcpConfig { client }`，未预览、文件原文变化或重新解析的链接目标变化时拒绝写入。`mcpConfigText {}` 返回包含 `mcpServers.autoemail` 的 JSON 文本，供其他工具复制。
- 客户端位置和写入方式见[总体设计](design.md#桌面端)。Claude Code 在 PATH 之外也查找原生安装的 `~/.local/bin`，macOS 再看 `/opt/homebrew/bin` 和 `/usr/local/bin`；Windows 再看用户与系统 WinGet 的 Links 目录及 `%APPDATA%\npm`。尊重 `CLAUDE_CONFIG_DIR`。由官方 CLI 添加用户级服务，替换旧项的添加失败时通过 `add-json` 恢复旧项；不打印客户端输出，避免带出配置中的凭据。桌面客户端用 serde_json 的 RawValue 保留其他配置的原始字节，现有文件权限随替换保留；新文件在 Unix 上为 `0600`。配置为符号链接时保留逻辑路径和解析目标，写入前与原子替换前重新解析并核对；失效链接报错，保留链接本身。测试注入临时配置路径和链接位置，不改真实客户端配置，不触发管理员授权，也不改注册表。

### 浏览器预览

`pnpm preview`（即 `cargo xtask web`）只用于开发，不进入安装包。先运行 `cargo xtask seed` 填入示例数据，再打开终端打印的网址；按 Ctrl+C 同时停止核心服务和 Vite，Unix 上收到 SIGTERM 时也会清理后退出。

- 使用当前工作树的 `.dev-data`，与桌面开发版共用数据目录锁和核心初始化，不能同时运行。界面的编辑会保存到这份真实数据里。
- 核心 HTTP 服务和 Vite 都只监听 `127.0.0.1`，启动时各自分配空闲端口，多个工作树可同时预览。Vite 通过 `--strictPort` 使用分配到的端口；请求必须同时带有本次启动的随机令牌和这个 Vite 页面的 Origin。令牌放在网址片段里，打开后从地址栏移除，保存在当前标签页的会话存储中以支持刷新。
- 不运行发信、收信、匹配、抓取、草稿生成、回信处理和待办提醒的后台循环；排队工作保留原状态，之后启动桌面开发版会继续处理。手动收信明确提示预览不支持；其他操作仍调用真实核心，主动测试连接或调用模型仍可能访问外部服务。
- 用 Tauri 官方的模拟接口代替桌面端的窗口和事件；核心不向页面推送事件，只有操作返回 `signed_out` 时由调用桥发出 `account-changed`，代替桌面版清除失效令牌时的通知。界面原有的轮询、操作后刷新照常工作。
- 启动状态返回成功，数据位置和版本来自本次核心；导出日志、导出表格、打开数据目录等原生能力明确提示预览不支持。外部链接交给浏览器打开。
- 仅在 Vite 的 `preview` 开发模式注入调用桥；正式 `pnpm --dir ui build` 和打包不会包含它。

### 自动更新

- 更新检查和下载留在 Rust 应用进程：应用可能在后台运行数天而不开窗口，不能依赖界面计时；不开放更新插件的界面权限。debug 构建不访问更新服务。自动检查失败只记日志，不发失败事件。
- 通过 `configure_client` 把检查和下载的 HTTP builder 交给 `net::Net::configure_http`，复用系统代理（含 SOCKS 和本机地址直连）与系统信任的 TLS 配置；每次新连接重新读取代理，不另做检测。插件固定在 2.14 小版本范围，因为这个回调的 reqwest 类型可能随插件的小版本变化。检查超时 30 秒，下载超时 30 分钟。
- 检查、下载和安装互斥；已有下载好的包时检查保留该包。下载由插件校验签名后才进入 `ready`，包只留在内存，退出后需重新下载。安装入口再次由插件校验。macOS 替换 `.app` 后调用 Tauri `restart()`；Windows 使用 NSIS passive 模式，由安装器重开应用。Windows 插件直接退出进程，`on_before_exit` 与正常退出共用 `before_exit`，关闭抓取窗口；发送中的邮件沿用启动恢复逻辑标为可能已发出。
- 正式更新公钥和 GitHub `latest.json` 地址在 `tauri.conf.json`，打包生成更新包与 `.sig`；macOS 的 `signingIdentity: "-"` 为整包加 ad-hoc 签名，不做公证。

## 发布

3.0 之前不运行发布工作流、不创建 Release。版本发布由维护者手动执行：

1. 在准备发布的提交里更新工作区 `Cargo.toml` 的版本，运行 `pnpm check` 和[手动检查](#手动检查)，按该版本创建并推送标签，例如 `v3.0.0`。
2. 准备给用户看的 Markdown 更新说明，包含主要变化和需要用户操作的事项；不放内部信息。打开 Actions 的“构建发布草稿”，选择含工作流的分支，输入已存在的标签和更新说明。工作流检出该标签，先核对标签是否恰好为 `v` 加工作区版本，不一致直接失败。
3. 仓库密钥 `TAURI_SIGNING_PRIVATE_KEY`、`TAURI_SIGNING_PRIVATE_KEY_PASSWORD` 分别保存更新签名私钥和密码。构建时读取这两个密钥，不放进文件或日志；本地 `pnpm package` 也通过这两个环境变量签名。公钥已经随应用配置提交，私钥必须另外备份，换掉公钥会使旧客户端无法更新。
4. 工作流分别构建 Apple Silicon macOS 与 Windows x64，使用 `tauri-apps/tauri-action@v1`，只创建普通版本的**草稿** Release，不自动公开。两个平台依次上传到同一草稿并合并 `latest.json`，避免更新清单互相覆盖。更新说明同时成为 Release 正文和清单的 `notes`。
5. 检查草稿中的 DMG、`.app.tar.gz` 与 `.sig`、NSIS `-setup.exe` 与 `.sig`，以及唯一的更新清单 `latest.json`。核对清单版本、说明、发布日期，以及 `darwin-aarch64`、`windows-x86_64` 的下载链接和签名；签名应与上传的 `.sig` 一致。没有 `latest.yml` 或 `appcast.xml`。
6. 下载草稿产物做全新安装与升级验收，macOS 执行 `codesign --verify --deep --strict --verbose=2 "Auto Email Sender.app"`。两个平台的检查都通过后，维护者手动发布草稿（不勾选预发布）。公开后从更新地址读取 `latest.json` 并再测一次真实升级。

工作流只响应 `workflow_dispatch`，push、PR 和推标签均不触发。构建失败可能留下不完整草稿，补跑通过并核对两平台产物后再发布；同一标签若已经公开，Action 会拒绝修改为草稿。

## 代码

- SQL 和其他长字符串写成多行（SQL 用 `r#"..."#` 按子句换行）。长字符串可能让 rustfmt 放弃所在语句的格式化，`cargo fmt --check` 照样通过；提交前看一眼这些语句。
- 规则多的逻辑写成纯函数，不碰数据库和网络：服务层读数据、调用纯函数、写回结果。
- 用普通的函数、模块和枚举。只有一种实现时不用 trait 对象，也不建类型层次。可变的全局状态只放在少数明确的地方。
- 不建 `utils`、`helpers`、`common` 这类杂物模块，不写只做转发导出的文件。
- 不可能缺失的值不写成可选：TypeScript 里不对它用 `?.` 和 `??`，Rust 里不包成 `Option`。
- 路径用 `std::path` 和 `node:path` 拼接。仓库脚本只写一份，用 Rust（xtask）或 Node 运行的 TypeScript，不成对写 `.sh` 和 `.ps1`。
- 依赖：JavaScript 只用 pnpm，用 `pnpm add` 加依赖，一次性的工具用 `pnpm dlx`，不手改版本号；Rust 用 `cargo add`。

## 异步和后台任务

- 耗 CPU 的工作（解析 HTML、PDF）放到 `spawn_blocking` 或专门的线程池，不占异步执行线程。
- 后台任务出错时，把错误记在任务上给用户看。只捕获能处理的错误，比如唯一约束冲突转成"已存在"。后台写数据库失败统一用 `db::Writes::retry` 重试。
- `email::tasks::next` 和 `mentor::matching::next` 在 `BEGIN IMMEDIATE` 写事务内领取。提交前取消的领取会回滚；若 COMMIT 已交给 SQLite、结果却因取消丢失，写锁保证它先于下次启动时的恢复提交，由恢复重新排队。
- `receive::outcome` 在收信事务入队后由宿主唤醒，开关、重试、继续、合并和恢复导师也会唤醒；空闲时等待通知，不轮询数据库。`email::outcome` 的队列按动作分别领取标结果和提取待办，共用领取计数、暂停、进度和模型额度，重启恢复处理中记录；两种动作各调用一次模型，与匹配、抓取和草稿生成使用同一个 `model::background::Limit`。个人资料中的递增领取计数跨队列行的删除和重建保存，取得共享额度后再读取当前默认模型和同意状态。`receive::reply_input` 共用取材与 6,000 字符预算，待办另带回信的本地日期和星期。结果分别由 `email::outcome`、`email::todos` 在核对领取后与出队一起提交。
- `email::todos` 保存待办，按本地日期和时间排序、换算提醒时刻；截止时间最后修改时刻用于排除用户刚看到的待办，修改日期或时间后重新计算提醒。排期先按截止日期分组，只读取本次需要通知的待办内容，并取下一次有效提醒时刻。`receive::reminders` 启动时补查，此后睡到最近的提醒时刻或被待办变化唤醒，不轮询数据库；开关、增改删、完成、导师回收／恢复／合并和 AI 提取都会唤醒。提醒文案由核心生成，桌面宿主调用系统通知，并推送 `todos-changed` 供界面刷新。
- `task::work` 直接筛选暂停、生成中或有失败的任务，只返回后台面板用到的摘要，不读取发送窗口；候选摘要与状态计数在同一个只读事务读取，计数和未完成判断与任务列表、详情共用。任务列表另行分页查询。
- `api::Context` 持有本次运行的域名查询状态：用小写域名原文作键，确定有无 MX 的结果不再重查，失败只记录 30 秒的重试间隔；不持久化。同一域名共享在途查询，最多同时查询 8 个域名。任务列表和批量批准通过回调读取已知问题并启动后台查询，不等 DNS；`checkMailDomain` 等待同一查询，失败后不受 30 秒间隔限制（写信框只在打开和联网后查）。
- `writing::prepare` 一次读取导师、个人资料和附件文件名，模板填充和模型请求共用这份取材；任务在取得共享模型额度后取材。
- 计时和超时用单调时钟。电脑睡眠唤醒后，重新检查到期的定时发送。

## 时间

- 分清两种时间：时刻存 UTC；用户说的"某天几点"按用户时区理解（见[数据模型](data-model.md#通用约定)）。
- 定时窗口按用户时区的日期和起止时间排，排好的计划发送时间存成时刻；显示时换成用户时区；模板里的日期按用户时区。
- 测试里固定时区和当前时间，覆盖跨午夜、窗口末尾和夏令时。
- 邮箱每日额度暂停和发送摘要的“今天”共用 `mailbox::pause::next_day_start`：从本地次日 0:00 起按 15 分钟步进，最多向后推进 24 小时，取第一个存在的时刻；重复时间取第一次。
- 窗口表单在输入和数据库读取边界解析为日期、时间；无效的存储文本返回解码错误。容量和排期只接收已校验的窗口。
- 创建时的容量和排期共用窗口换算；已结束和夏令时跳过的窗口不计容量。界面从核心读取可用窗口数、封数和下一次容量变化的窗口结束时刻，不自行计算；在该时刻和窗口重新获得焦点时刷新，不每秒轮询。
- 排期使用 Chrono。夏令时回拨的重复时间取第一次；跳时导致窗口边界不存在时跳过这个窗口，不移到用户未选的时间。手动改期只保留一小时的发送机会，不再自动接回任务窗口。

  - 批量审核时切换草稿前先保存。
  - 列表的筛选、排序和翻页放进网址（TanStack Router 的 search 参数），返回时还在。

## 数据库

- 打开第一个连接前，`db` 先在一个线程上调用一次 `sqlite3_initialize()`，避开 SQLite 在 ARM 上多个线程同时首次初始化的竞争：`db::open` 建池前调用；测试经由 `db::MIGRATOR`（sqlx 建测试库前会先读它）触发，自己开第一个池的测试先 `LazyLock::force(&db::MIGRATOR)`。
- 迁移只往后加，已经执行过的迁移不能修改，开发版和预览版也一样；sqlx 会校验迁移内容，修改旧迁移会让已有数据库无法打开。
- 迁移也把日志模式设成 WAL：`sqlx::test` 直接用迁移建库，这样测试和应用一样读写不互相等待。`synchronous` 是连接级的设置，迁移设不了，应用的 NORMAL 由 `db::open` 设置。
- SQLite 测试在开发依赖里打开 `db` 的 `testing` 功能，它在上面那次初始化里注册一个连接入口，让新连接默认 `synchronous = OFF`：测试建库不经过 `db::open`，刷盘让 Windows 上的测试慢好几倍，而断电后的持久性测试本来也测不出。`db::open` 显式设的 NORMAL 照样生效；正式构建不带开发依赖，没有这个入口。
- 每次发布前，用上一版的真实数据库（去掉个人信息后作为测试数据）测一遍升级。
- 新的高频查询先用 `EXPLAIN QUERY PLAN` 确认走了索引；列表只取要显示的列，并且分页。
- 编号用 `INTEGER PRIMARY KEY AUTOINCREMENT`：删掉的编号不再分配给新的一行，界面里按编号缓存的数据和进行中的保存就不会把两样东西混在一起。
- 一次要读好几条语句的（比如列表先取本页的编号再取行），放在同一个只读事务里，读到的是同一个时刻的数据。
- 需要先读取再写入的顶层操作，用 `BEGIN IMMEDIATE` 在首条读取前取得写锁；不靠无变化更新或占位记录拿锁。在默认的延迟事务里先读后写，别的连接恰好在中间提交时会立即报"database is locked"，不会等待。冲突靠唯一约束发现，失败后再查原因告诉用户。
- 一条语句里的参数要么都写 `?`，要么都写 `?1` 这样的编号：两种混用时 sqlx 绑定的位置和 SQLite 算的不一样，会把值绑错。
- 可选的筛选条件写成 `(?1 IS NULL OR …)`，一条查询就能在编译时检查；含相关子查询的值与“未填写”分支用 `CASE`，确保未启用的分支不会求值。条件只引用列表的主表，别的表上的条件写成 `IN` 子查询：SQLite 每次查询只算一遍这个集合，不会为主表的每一行连接一次别的表。
- 统计的三个部分分别提供一次操作；同一操作中的查询在同一个只读事务内读取。联系事件视图与 `mentor_contact_live` 共用；首次发出和首次回信的聚合视图不存数据。联系数字、院校对比、趋势和导师概览中的匹配分布、资料完整度和学校分布分别查询，基准逐条检查 50 毫秒预算。
- 基准：`cargo xtask bench` 生成[数据模型](data-model.md#性能)里那个规模的数据，测高频查询并检查预算；新的高频查询写好后加进去。改表结构或高频查询时跑一遍，超出预算当 bug 修。

## 抓取基础

抓取日志统一放在只含编号的 `crawl{id}` span 里。异步任务用 `.instrument`（或 `#[tracing::instrument]`），阻塞线程和 WebView 回调显式携带同一 span。INFO 级记录开始、继续、暂停及原因、取消、结束统计，页面的网址、种类、HTTP／浏览器读取结果与耗时、状态码、跳转、证书放宽、浏览器接管原因和拦截，以及模型步骤、用量、耗时和失败类别；补全沿用同一约定。每页只写几条关键事实，不逐个链接或候选记录。不写网页正文、模型输入输出、导师姓名和邮箱、API Key；外部错误可能含这些内容，只记可安全公开的类别。公开网页的网址可以写。日志的位置和保留规则见[数据模型](data-model.md#通用约定)。

抓取基础使用 `crawl::Scope` 为本站页面和名单里实际出现的个人页生成访问目标；多个任务共用一个 `crawl::fetch::Fetcher`，才能共用网站的请求上限。`fetch` 在阻塞线程解析 HTML，纯解析入口 `crawl::parse` 供离线样本和已经取得的 HTML 使用。

解析材料按页面顺序返回文字块：每个块级元素里直接的文字（含行内元素）成一块；中间有子块时按顺序分段，行内标签直接连接原始文字。`Unit.path` 从根到所属块记录原始 DOM 的元素序号；`line_starts` 记录 `br` 后的行首位置（块首隐含为 0），不把 HTML 源码排版的换行当作行首；`in_footer_or_nav` 标记页脚／导航内的块。链接和邮箱证据记在所在块上，所有文字位置均为块内 UTF-8 字节位置；文字证据保留地址原写法区间，属性证据另记原始 DOM 的元素序号、属性名和原值。链接和材料都是数据，不是可执行 HTML。浏览器接管原因单独返回，已有文字仍保留。

解析不猜哪些块属于同一个人（卡片的写法太多，猜错了会把邮箱配给别人）。归属在模型提取之后由 `crawl::owns_email(material, names, target_names, address)` 核对，`names` 是这一页模型提取出的全部导师姓名，`target_names` 是同一位目标导师的姓名和别名；名单提取只传入原来的一个姓名。邮箱按正文的文字或属性证据匹配。

- 姓名的出现处：忽略空白比较；被另一位导师更长的姓名包含的那一处不算（"王明"在"王明华"里）。图片链接的替代文字（`alt`、`title`、`aria-label`）算作链接所在位置的文字。
- 打头的姓名：在块的开头，或者块里换行后的行首。正文句子中间提到的姓名（"与李四合作"）不是打头的：它不能让李四认邮箱，但会挡住别人，宁可漏认。
- 邮箱满足下面一条才认：
  1. 这位导师的姓名打头，它和邮箱最近的共同上级里没有其他导师的姓名（任何出现处都算）。
  2. 平铺：把最近的共同上级下面直接的子元素和它自己的文字段按页面顺序排开，姓名所在的那一项以这位导师的姓名打头，邮箱所在的项在它后面，从姓名之后到邮箱之前没有其他导师的姓名（任何出现处都算）。邮箱在页脚（`footer`）或导航（`nav`）里时不适用。
  3. 同一块：这位导师的姓名打头，邮箱位置不早于姓名开头，中间没有其他导师的姓名（任何出现处都算）。
- 三条都只从打头的姓名起算。核对防的是名单里相邻导师串配；句子本身以同事姓名开头（"李四教授与本人共同指导"）这类写法仍可能放行，这要模型先把邮箱配给李四，不再为它细分规则。
- 姓名出现几次的，有一处满足就认。哪条都不满足的不认这个邮箱，这位导师按缺邮箱处理（可以补全）：判断不了时宁可少认，不配错人。

- 网址先完成主机规范化，再对最终主机类型检查公开地址；构造 `PageUrl` 后不再改变主机。
- 邮箱先匹配完整地址片段，只在片段内还原明确的 `at`、`dot` 等混淆写法，保留自然语言句点两侧的分隔和地址外面的引号。
- 翻页控件分类和容器上下文共用一份结果；数字页码按同容器里的连续页码或只差页码的名单网址识别，不依赖 class 名。“首页”只有在分页器中或指向同组名单网址时才算翻页，普通导航保留在链接中。按钮、可操作的 `input` 和脚本绑定的分页控件没有静态目标时返回需要浏览器；禁用、隐藏、文本输入和已到末页的前进控件不算可翻页，单独的 `javascript:void(0)` 不作为交互证据。只有可执行的 JavaScript／module 脚本可作为事件绑定线索，JSON 等数据脚本不算。
- `onclick` 和 `javascript:` 链接只提取完整的静态导航赋值或调用，不把动态表达式的字符串前缀当作网址。没有实际正文（允许挂载点内有加载占位文字）时，结合挂载点、脚本入口与 `noscript` 提示识别应用空壳，不以脚本数量判断少量文字的静态页。判断名单是否已有导师链接时，空地址、只有片段和非 HTTP(S) 地址不算。

### 隐藏浏览器读取

桌面 runner 在同一次领取里先读 HTTP，遇到浏览器接管原因后调用 `crawl::browser::Browser`，取得最终网址和 HTML，再交给同一套 `page` 解析和导师提取。浏览器预览不提供实现，仍保留“需要浏览器”的结果；测试使用假的实现。HTTP 文字先按领取保存，浏览器读取失败保留它和中文原因；浏览器返回的内容仍需渲染、解密或验证时记失败。可重放的按钮翻页不再作为未完成的接管原因。浏览器 DOM 中已变为可见的加密字段按解密后的文字解析，仍隐藏的字段保留接管原因。

- `app::browser` 每次新建隐藏、incognito 的 `WebviewWindow`，会话不跨页面共享；全应用最多同时 2 个，多余的排队；额度交给窗口持有，收到原生 `Destroyed` 事件才归还，创建失败时直接归还。完成、失败、领取失效、暂停、取消或应用退出时关闭窗口。等待浏览器时每 500 毫秒核验原领取，结果写入仍由原领取计数和运行状态约束。
- 页面加载完成后，每 500 毫秒读取同一份快照：`readyState`、网址、文档离开标记、正文文字、链接 `href` 和图片 `alt`；`complete`、未离开当前文档且快照连续 1.5 秒不变才读取最终网址和整页 HTML。材料变化会重新计时，翻页前后的变化判断也使用这份快照。窗口的初始化脚本（`crates/app/src/browser/navigation.js`）在每次顶层导航、页面脚本运行前登记监听。有 Navigation API 时，`navigate` 标记跨文档导航开始，`navigatesuccess` 和 `navigateerror` 清除标记，让被页面接管或取消的导航继续进入就绪判断；同文档导航与 iframe 不标记主文档离开。没有 Navigation API 的旧系统 WebKit 上，自动或点击后整页跳转而旧页面又改了内容时，仍可能在新页面到达前就读取。每次加载或点击后最多等待 20 秒；HTML 与 HTTP 共用 4 MiB 上限。证书校验使用系统 WebView 默认行为，不放行；HTTP 已检测到证书异常且浏览器加载超时时，说明网站证书有问题。
- 主窗口独占界面 capability，抓取窗口没有 capability。导航仅对不发网络请求的 `about:blank`、`about:srcdoc` 两个精确值直接放行，不改变当前网络网址或计入跳转次数；其他导航、重定向、脚本跳转和刷新均使用 `PageTarget` 的公开网址及同网站规则，每次打开或点击最多跟随 5 次跳转；站外个人页的授权仍来自名单中实际出现的链接。拒绝新窗口和下载。不自行解析 DNS，遵循代理的 fake-ip 行为。
- 每次只追加一个向前的按钮翻页步骤（目标页码和原始控件文字），页面按网址和有序步骤列表去重，并受原有 60 页上限约束。读取后续页时重新打开名单网址，按解析器相同的取值顺序读取控件的 `value`、可见文字和自身／子图片替代文字，找可见、未禁用且标签相同的控件点击，`input` 仅包含 `button`、`submit`、`image` 三种类型；每步比较正文文字、链接 `href` 和图片 `alt`，材料变化且页面稳定后再继续，点击后材料没有变化仍记超时失败，不共享其他页面的窗口。静态 URL 翻页仍沿用 HTTP 队列。

### 抓取流程和候选审核

- `crawl::queue` 用页面表的 `work_state`、`claim`、起点范围和深度保存待访问工作；页面结果与发现的后续页面、候选在同一个写事务中提交。暂停、取消和重启恢复都递增领取计数，旧请求不能再写结果；已经消费的模型用量仍入账。取消丢弃未访问的页面计划，保留已取得的页面和候选；之后单页重试只重试所选页面及其新发现的必要后续页面。页面的文字在获取后先按领取计数保存，模型出错也保留。
- 选路只给模型标题和本站链接的编号、文字；翻页走解析结果。名单按文字块之间的边界分段，每段以 6000 字为目标，单个更长的块不截断，避免拆散姓名和联系方式。提取完全部段的姓名再统一核对邮箱归属。同一位导师有几个已核实的个人页时，只自动访问最先记录的一个，所有已核实个人页保存到候选的对应关系中；合并时去掉其他尚未开始的个人页队列，已在途的结果仍可定位保留的候选。提示词明确网页内容是数据，模型不能执行其中的要求，链接编号和邮箱都由程序对照实际页面。
- 模型额度使用 `model::background::Limit` 的同一个实例，与匹配和草稿生成共享。抓取固定开始时的配置编号，继续、重试沿用，配置被删才选默认配置；整体错误暂停该抓取，每次取得额度后重新读取配置和同意状态，配置失效就作废领取、重新排队。限流使用服务商的 `Retry-After`，每次选路、分段提取或格式纠正请求前都检查冷却，在途结果照常保存。
- `mentor::intake` 统一处理表格和候选的邮箱分组、对应、补充和用户选择，并在调用方事务里写入；`mentor_name` 保存按比较规则规范化的姓名、别名原文，随导师资料与搜索索引一起维护，用于索引查询，不使用哈希。候选的比较用姓名、学校和导师单位的比较用学校同样保存规范化原文；分类在 SQL 中先确定本页编号和总数，再只读取本页资料，导师变更后即时生效。补充预览共用目标导师和实际新增的字段、列表内容。

- 信息补全使用同一页面队列的 `enrich_profile`、`enrich_child` 种类，`candidate_id` 定位候选；普通抓取页面与补全页面分别去重，补全重新开始时替换该候选的上一轮页面记录。补全领取不固定模型编号，请求前复核当前默认配置和同意。混跑时摘要提供实际需要的模型配置编号，继续或重试前逐个确认尚未同意的配置。`stage = enrich` 表示只剩补全页面，`enrich_remaining` 单独统计待审核且尚在补全的候选；和普通抓取同时运行时分别显示进度。
