# Crawl Mentors Skill 前向评测记录

日期：2026-07-30

目标：验证 `.agents/skills/crawl-mentors-to-xlsx` 能让独立 Codex 代理从真实高校官网取证、生成安全 10 列 XLSX，并通过 Skill 校验器与 Auto Email Sender 的真实导入解析器。

## 第一轮

每个代理只获得 Skill 路径、官网入口、最多 5 位教师的范围和独立 `/tmp` 输出目录；代理不得修改仓库。

| 官网 | 可导入 | 待复核 | 来源 | Skill 校验 | 真实解析器 |
| --- | ---: | ---: | ---: | --- | --- |
| 清华大学计算机系 | 5 | 0 | 12 | 通过 | 5 条，失败 0 |
| UC Berkeley EECS | 5 | 2 | 12 | 通过 | 5 条，失败 0 |
| HKUST CSE | 5 | 0 | 12 | 通过 | 5 条，失败 0 |

主要发现：

- 清华旧入口返回官方 404 跳转页；代理能沿校内页面找到现行目录，并分别记录旧入口、跳转落点和新目录。
- Berkeley 目录包含 Emeritus/Emerita、限定职称和外部个人站；代理正确分流退休人员并保留官方域内证据。
- HKUST 邮箱使用 HTML 实体混淆；代理完成可逆还原，没有按姓名猜邮箱。
- 三份工作簿均为活动且第一张的 `Professors` 安全 10 列，公式和错误值为 0。
- 视觉检查在部分子代理环境中触发了不必要的 LibreOffice、字体缓存或桌面 UI 尝试，最长产生约 229 秒无效等待。
- `sources.role` 和 `sources.status` 的枚举只在生成器错误中显现，导致一次可避免的重新生成。

据此迭代：

- 在主 Skill 中直接列出所有 JSON 枚举。
- 补充限定职称映射、外部个人站边界、旧入口迁移、DOM 紧凑提取、组织层级和论文选择规则。
- 视觉预览改为“已有工具、一次、限时 60 秒”；禁止安装字体、生成 PDF 或长时间驱动 GUI。
- 生成器和校验器直接输出活动表、各表尺寸、公式数和错误值数。
- 增加来源唯一账本、不可转义论文分隔符、枚举和错误值回归测试。

## 第二轮

新代理只按名称调用 `$crawl-mentors-to-xlsx`，不提供文件路径，用于验证仓库自动发现和迭代效果。

| 场景 | 结果 | 生成尝试 | 终止行为 |
| --- | --- | ---: | --- |
| HKUST CSE 前 2 位 | 2 条可导入、0 复核、7 来源 | 1 | 无渲染器时及时停止，Skill 与真实解析器均通过 |
| Oxford Academic Staff | 环境代理不可达；0 条可导入、1 条 `fetch_failed`、2 条失败来源 | 1 | 未猜测教师信息，生成合规的失败分流工作簿 |

HKUST 第二轮从开始到报告完成约 4 分 52 秒，生成首次成功。两名第二轮代理均确认 Skill 可从 `.agents/skills` 自动发现。

## 保留的限制

- 官网内容和结构会变化，前向样本不是永久数据基线；自动测试只冻结导入契约和生成器行为。
- 没有现成渲染器时只能完成结构检查，最终交付必须明确报告“视觉预览未执行”。
- 评测调用了系统真实文件解析器，但没有把测试数据写入用户数据库，也没有自动上传文件。

## 第三轮：四个完整中文学院目录

日期：2026-07-31

四个独立代理获得 Skill 和一个官网入口，按完整目录抓取并写入各自的 `/tmp` 输出目录；代理不得修改仓库。所有结果都通过 Skill 独立校验器、Auto Email Sender 真实导入解析器和三个工作表的 Artifact Tool 只读检查。

| 官网 | 候选 | 可导入 | 待复核 | 来源 | 真实解析器 |
| --- | ---: | ---: | ---: | ---: | --- |
| 中南大学电子信息学院 | 81 | 42 | 39 | 69 | 42 条，失败 0 |
| 北京交通大学计算机科学与技术学院 | 216 | 144 | 72 | 258 | 144 条，失败 0 |
| 山东大学集成电路学院 | 73 | 55 | 18 | 83 | 55 条，失败 0 |
| 电子科技大学计算机学院 | 189 | 173 | 16 | 190 | 173 条，失败 0 |

主要发现：

- 北交入口由 iframe 加载动态目录，需要从同校官方 JavaScript 确认学院代码和页面公开调用的只读 API。代理曾把经过终端摘要的输出再次解析，污染候选编号并产生 37 个无效调试请求。
- 电子科大普通 HTTP 只返回客户端防护页，浏览器同域 `fetch` 才能读取正文；单个浏览器脚本连续处理约 70 个详情页后提前结束，改为每批 20 人立即持久化后稳定完成 189 人。
- 电子科大页面把“【研究方向】”拆成多个文本节点，旧提取逻辑曾留下 `】` 残片；3 条无法可靠分离的长简介被保守留空。
- 电子科大目录中的工程师、实验师等复合职称暴露了子串映射风险，例如“教授级高级工程师”不能被映射为“教授”。
- 山东大学 73 个个人主页均可用静态 HTML 获取；邮箱只能来自个人页或页面自身公开的同域解密接口，未按姓名猜测。两条无分隔损坏或多邮箱冲突的字段进入复核。

据此迭代：

- 增加动态目录探索、公开 API 使用边界、页面总数与唯一候选数强制对账。
- 要求候选发现后立即直写 UTF-8 JSON，个人页每 10 至 20 人保存检查点，并从已处理 URL 续跑；禁止从日志或摘要结果反向解析结构化数据。
- 在机器契约中增加职称排除标记，并在所有别名和中文子串映射前执行，覆盖工程师、实验师、荣休、访问、博士后等复合身份。
- 收紧研究方向语义边界：重组拆分标题、丢弃纯标点节点、不跨入个人简介；长段落不能无损分离时留空。
- 有 Artifact Tool 时对生成后的三个工作表分别做只读区域检查和公式错误扫描，不使用它重新导出工作簿。

修订后的独立动态页前向测试还暴露了“浏览器渲染”和“绕过挑战”的边界歧义：代理看到 HTTP 202 JavaScript 中间页后曾直接停止，随后发现可用的 ego-browser 默认继承用户登录态，不符合公开抓取的无 Cookie 原则。规则进一步明确为优先复用环境中已有的临时全新浏览器上下文或一次性用户目录，让浏览器像普通访客一样自然加载公开页面的一方脚本；仍禁止验证码求解、挑战脚本逆向、令牌提取或重放。只有继承登录态的浏览器时需先取得用户明确同意，浏览器最终仍只有挑战页时必须停止。

第二次前向探针使用现成 Playwright 和全新 Chrome 用户目录，导航前 Cookie 数为 0；目录最终仍返回 HTTP 202，正文与链接数均为 0，并出现同站脚本后续 400。代理按新版规则停止，没有继续猜测接口或重放令牌。这验证了安全降级和发现阶段检查点，但也说明电子科大这类站点在严格无 Cookie 环境中可能只能交付 `fetch_failed`；若要改用会继承登录态的浏览器，必须让用户先明确选择。
