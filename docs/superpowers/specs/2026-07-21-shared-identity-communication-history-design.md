# 多身份共享通信记录设计

## 1. 背景

当前系统以发件身份作为通信数据的读取边界。用户在顶部选择一个身份后，首页导师状态、工作区通信时间线和统计面板都会向后端传递单个 `identity_id`，后端只查询该身份关联的 `EmailTask` 与 `EmailLog`。

在实际使用中，用户可能会为同一套联系工作配置多个发件身份，例如不同邮箱、不同发件通道，或者需要共同查看历史的多个身份。此时，同一位导师与这些身份之间的通信记录被拆分展示，用户必须反复切换身份才能判断是否已经联系、由哪个邮箱发出、回复进入了哪个邮箱。

本设计引入“通信共享组”：用户可以把多个身份加入同一个共享组。选择组内任一身份时，系统在所有通信展示位置读取并合并组内身份的真实通信记录，同时继续使用当前选中的单一身份执行草稿、任务和发送操作。

现有通信记录不迁移、不复制、不修改归属。共享组只改变读取范围和派生展示口径。

## 2. 设计目标

- 用户可以选择两个或更多身份组成一个通信共享组。
- 选择组内任一身份时，工作区展示该组与当前导师的合并通信时间线。
- 首页的已联系、已回复、发送次数和最后通信时间基于共享组计算。
- 统计面板中的真实发送、联系和回复数据基于共享组计算。
- 每条通信记录明确展示由哪个身份发出或由哪个身份收取。
- 当前任务、草稿、材料、模板、SMTP、发送限额和发送动作始终属于当前选中的单一身份。
- 未加入共享组的身份保持现有行为，不产生兼容性变化。
- 后端统一解析共享范围，避免每个前端页面自行拼接身份列表。
- 跨身份同步到的同一封物理邮件在合并视图中不重复展示或统计。

## 3. 非目标

- 不复制、迁移或重新绑定现有 `email_logs`、`email_tasks`。
- 不共享身份材料、模板、SMTP/IMAP 密码、发送限额或冷却时间。
- 不把多个身份合并成一个新的发件身份。
- 不合并任务中心中的批量任务、单封任务或任务状态。
- 不自动阻止组内不同身份联系同一位导师。
- 不跨身份更新 `EmailTask.is_replied`、`status` 或任务父子关系。
- 不构建支持任意方向关系的“A 可以看 B，但 B 不能看 A”权限模型。
- 不允许同一身份同时属于多个通信共享组。
- 第一版不提供按来源身份过滤时间线的高级筛选器。
- 第一版不为通信共享组提供自定义名称、颜色或排序。

## 4. 核心概念

### 4.1 当前操作身份

当前操作身份是用户在顶部身份选择器中选中的唯一身份。它决定：

- 当前任务及其状态。
- 当前草稿和已选择材料。
- 发件人名称与发件邮箱。
- SMTP/IMAP 配置。
- 模板与生成模式。
- 发送限额、发送间隔与域名冷却。
- 新建、审批、定时、发送、重试和跟进操作的归属。

顶部身份选择器继续保持单选，不改成多选。

### 4.2 通信共享组

通信共享组是一组对称、可传递的身份成员关系：

- A 与 B 在同一组时，选择 A 或 B 都能看到 A、B 的合并通信记录。
- 如果 B 与 C 也需要共享，则 A、B、C 必须属于同一个组。
- 一个身份最多属于一个组。
- 一个有效共享组至少包含两个身份。
- 未加入任何组的身份视为只和自己共享。

### 4.3 通信查看范围

通信查看范围是后端根据当前操作身份解析出的身份 ID 集合：

```text
未分组身份 A -> [A]
共享组 A、B、C，当前身份 A -> [A, B, C]
共享组 A、B、C，当前身份 B -> [A, B, C]
```

共享范围只用于读取真实通信记录和计算通信派生数据，不自动应用于任务查询。

### 4.4 逻辑通信事件

一条 `EmailLog` 是一个身份下的持久记录。多个身份可能从各自邮箱同步到同一封物理邮件，因此合并视图需要把这些记录折叠成一个“逻辑通信事件”。

逻辑通信事件保留所有来源身份，用于显示“由哪些身份发出或收取”，但在时间线和统计中只计一次。

## 5. 已确认产品口径

### 5.1 读取合并，写入不合并

共享组影响读取，不改变写操作归属：

```text
当前身份 A
共享组成员 A、B

通信时间线：读取 A + B
首页联系状态：读取 A + B 的真实通信
统计发送/回复：读取 A + B 的真实通信

当前任务：只读取 A
草稿与材料：只读取 A
发送动作：只使用 A
任务中心：只展示 A
```

### 5.2 不自动改变发送规则

第一版严格定位为展示合并：

- B 已经联系某导师时，首页在 A 下会显示该导师“已联系”。
- 系统仍允许用户为 A 创建任务并向该导师发送邮件。
- A、B 的每日限额、发送间隔和同域名冷却分别计算。
- 现有重复发送、任务幂等和调度规则不扩大到共享组。

如果后续需要“共享组内禁止重复联系”，应作为独立业务规则设计，不能通过修改展示查询隐式实现。

### 5.3 身份来源必须可见

合并后的每条真实通信必须标明身份来源：

- 发件记录显示“由 A 发出”。
- 收件记录显示“由 B 收取”。
- 同一封邮件被多个身份同步时显示“由 A、B 收取”。

身份来源使用身份的 `profile_name`；必要时同时展示 `email_address`，避免重名身份无法区分。

## 6. 功能范围矩阵

| 功能区域 | 使用共享范围 | 仍使用当前身份 | 说明 |
| --- | --- | --- | --- |
| 工作区真实通信时间线 | 是 | 否 | 合并组内 `sent`、`received` 记录。 |
| 工作区当前任务 | 否 | 是 | 当前身份最新任务保持独立。 |
| 工作区草稿、材料和发送动作 | 否 | 是 | 不允许共享范围改变发件配置。 |
| 首页已联系/已回复 | 是 | 否 | 任一组成员有真实通信即可推进关系状态。 |
| 首页发送次数和最后通信时间 | 是 | 否 | 基于去重后的共享通信事件。 |
| 首页匹配分数 | 否 | 是 | 匹配分析仍属于当前身份任务。 |
| 首页准备中/待发送/失败 | 否 | 是 | 没有真实通信时回退到当前身份任务状态。 |
| 统计发送量、联系导师数、回复数、回复率 | 是 | 否 | 基于共享通信事件。 |
| 统计发送/回复趋势 | 是 | 否 | 基于共享通信事件时间。 |
| 统计待审核、定时、失败 | 否 | 是 | 属于当前身份的执行状态。 |
| 统计任务漏斗、任务状态分布、待跟进列表 | 否 | 是 | 不合并其他身份任务。 |
| 任务中心列表和批次计数 | 否 | 是 | 保持任务归属和操作边界。 |
| 从任务中心进入工作区 | 时间线是 | 任务是 | 以该任务身份作为当前操作身份。 |
| 测试发信历史 | 否 | 是 | 不属于导师真实通信共享范围。 |
| Token 使用统计 | 否 | 是/现有筛选 | 不因共享组改变。 |

## 7. 数据模型

### 7.1 新增共享组表

新增 `identity_communication_groups`：

- `id`：主键。
- `created_at`：创建时间。
- `updated_at`：最后一次成员变更时间。

第一版不保存组名。前端使用成员身份名称生成摘要，例如“A、B”或“A 等 3 个身份”。

### 7.2 身份关联

`identity_profiles` 新增：

- `communication_group_id`：可空外键，指向 `identity_communication_groups.id`。

约束和删除语义：

- 一个身份只能有一个 `communication_group_id`。
- `communication_group_id` 建立普通索引。
- 删除共享组时对身份执行 `SET NULL`，不得删除身份、任务或通信记录。
- 删除身份时沿用现有身份删除语义；共享组只移除该成员。
- 成员删除后组内少于两个身份时，服务层自动解散该组并把剩余成员设为未分组。

### 7.3 不修改通信表

以下现有字段继续作为共享读取基础：

- `EmailLog.identity_id`：记录所属邮箱身份。
- `EmailLog.professor_id`：记录所属导师。
- `EmailLog.direction`：`sent`、`received` 或 `draft`。
- `EmailLog.normalized_message_id`。
- `EmailLog.rfc_message_id`。
- `EmailLog.message_fingerprint`。
- `EmailLog.created_at`。

不改变现有唯一索引。跨身份重复记录允许继续独立持久化，由读取层折叠。

## 8. 共享组管理规则

### 8.1 创建

- 用户至少选择两个现有身份。
- 身份 ID 必须去重。
- 所有身份必须存在。
- 如果选中身份已经属于其他共享组，默认返回冲突，不静默拆组或合组。
- 用户确认合并已有组后，后端在一个事务中把涉及的所有成员合并到一个组。

### 8.2 编辑成员

- 新成员加入后立即获得该组的通信查看范围。
- 被移除成员立即回到独立范围。
- 编辑不复制或删除任何通信记录。
- 编辑后的成员少于两个时，前端引导用户解散共享组；后端不保存单成员组。
- 涉及其他共享组时沿用显式确认合并规则。

### 8.3 解散

- 解散只清空成员的 `communication_group_id` 并删除组记录。
- 所有身份、任务、通信记录和同步状态保持不变。
- 解散后各身份只能看到自己的通信记录。

### 8.4 删除身份

删除身份沿用现有数据删除策略。如果现有策略会级联删除该身份的 `EmailLog`，这些记录也会从共享时间线中消失。

因此身份删除确认需要增加说明：该身份产生或同步的通信记录可能从共享组历史中永久消失。把身份移出共享组不会删除记录，只有删除身份本身才沿用现有删除行为。

## 9. 后端共享范围解析

新增集中式服务，例如：

```python
@dataclass(frozen=True)
class IdentityCommunicationScope:
    active_identity_id: int
    identity_ids: tuple[int, ...]


async def resolve_identity_communication_scope(
    session: AsyncSession,
    *,
    active_identity_id: int,
) -> IdentityCommunicationScope:
    ...
```

解析规则：

1. 当前身份不存在时沿用现有“未找到身份”错误。
2. 当前身份没有 `communication_group_id` 时返回自身。
3. 当前身份属于共享组时，一次查询返回全部有效成员。
4. 返回值始终包含当前身份。
5. 成员 ID 使用稳定顺序，建议当前身份优先，其余按 ID 升序。
6. 所有读取入口必须复用该服务，不允许在各 API 内重复实现成员查询。

现有 API 继续接收单个 `identity_id`。该参数表示当前操作身份，不改成由客户端传任意 `identity_ids`。

## 10. 逻辑通信事件与跨身份去重

### 10.1 去重键

在同一导师、同一方向下，按以下优先级构建逻辑事件键：

1. `normalized_message_id` 存在时：`professor_id + direction + normalized_message_id`。
2. 否则使用规范化后的 `rfc_message_id`。
3. 否则使用 `message_fingerprint`。
4. 都不存在时使用 `EmailLog.id`，不尝试按主题或正文猜测去重。

同一物理邮件关联不同导师时仍按导师分别计数，保持现有“导师通信记录”口径。

### 10.2 合并规则

- 同一逻辑事件只生成一个时间线项目。
- `source_identities` 合并所有来源身份并去重。
- 时间使用成员记录中最早的 `created_at`。
- 代表 ID 使用最小的 `EmailLog.id`，保证后续发现新的重复记录时前端 key 保持稳定。
- 正文优先保留具备有效 HTML 的记录，其次选择非空文本最完整的记录。
- 主题、RFC Message-ID、回复头等缺失字段允许从同组记录补齐。
- `sent` 与 `received` 永不互相折叠。
- `draft` 不进入跨身份逻辑事件集合。
- 同正文但 Message-ID 或 fingerprint 不同的邮件视为不同事件。

### 10.3 复用要求

工作区、首页联系状态和统计面板必须共享同一去重口径。不能出现工作区显示一封、首页发送次数计算两封、统计趋势又计算成另一结果的情况。

建议把加载和折叠逻辑收敛在独立的通信读取服务中，而不是由前端合并多个接口结果。

## 11. 工作区行为

### 11.1 Thread 组成

工作区 thread 同时包含两种范围：

- `identity`、`current_task`、`material_options`、草稿：当前操作身份。
- `messages`：通信共享范围。

当前任务仍按 `professor_id + active_identity_id` 查找，不从其他组成员选择“最新任务”。

### 11.2 消息查询

真实通信查询：

```text
professor_id = 当前导师
AND identity_id IN 通信查看范围
AND direction IN (sent, received)
```

当前草稿查询：

```text
professor_id = 当前导师
AND identity_id = 当前操作身份
AND direction = draft
AND email_task_id = 当前任务
```

两部分在服务端组合，最终按 `created_at ASC, id ASC` 稳定排序。其他身份的草稿不得进入当前工作区。

### 11.3 Thread DTO

`WorkspaceThreadRead` 增加：

- `communication_scope`：当前共享范围内的身份摘要列表。

`WorkspaceMessageRead` 增加：

- `source_identities`：产生或同步该逻辑通信事件的身份摘要列表。

身份摘要至少包含：

- `id`
- `profile_name`
- `email_address`

现有 `identity` 字段继续表示当前操作身份，不能改成共享组。

### 11.4 所有 Thread 返回入口保持一致

以下类型的接口在动作完成后都会返回 `WorkspaceThreadRead`，必须统一使用共享范围：

- 工作区 GET。
- ensure task。
- 手动刷新回复。
- 草稿生成、重写、保存和材料修改。
- 审批、立即发送、定时发送和取消定时。
- 继续手动联系和创建跟进任务。
- 批量任务项目的 thread、重生成和审批接口。

不能只修改工作区 GET，否则用户完成动作后时间线会暂时退回单身份，直到下一次刷新。

### 11.5 工作区 UI

- 页面继续明确展示当前操作身份。
- 通信区域显示“共享通信 · N 个身份”；未分组时不显示额外标识。
- 每个真实消息气泡显示来源身份名称。
- 身份重名时追加邮箱地址。
- 默认展示全部共享消息，不提供来源筛选器。
- 消息左右方向仍只由 `sent`、`received` 决定，不按具体身份改变。
- 当前身份没有任务但共享组存在历史记录时，仍展示历史记录；无任务空状态只影响编辑和发送区域。
- 切换到同组另一个身份时，历史范围保持一致，但当前任务、材料和草稿重新加载。
- 现有未保存草稿切换保护继续生效。

## 12. 手动刷新与后台同步

### 12.1 后台同步

现有后台 IMAP 同步继续按身份独立运行：

- 每个身份使用自己的 IMAP 配置和同步游标。
- 每条同步记录继续写入实际邮箱对应的 `identity_id`。
- 共享组不建立新的联合游标。
- 一个邮箱同步失败不影响其他邮箱后台同步。

### 12.2 工作区手动刷新

用户点击“刷新通信记录”时，应对共享范围内所有具备有效 IMAP 配置的身份执行该导师的现有定向同步，而不是只刷新当前身份。

要求：

- 复用现有身份级锁和服务商限流机制。
- 不绕过每个身份自己的同步状态和去重逻辑。
- 允许部分成功。
- 成功身份写入的记录必须正常返回和展示。
- 失败身份以警告形式返回，不把整个 thread 请求变成失败。
- 当前操作身份同步失败时也保留已成功加载的本地历史。

`WorkspaceThreadRead` 可增加可选的 `sync_warnings`，每项包含失败身份 ID、身份名称和可展示错误摘要。普通 GET 返回空数组。

## 13. 首页导师状态

### 13.1 共享通信字段

以下字段基于通信查看范围和去重后的逻辑通信事件：

- `sent_count`
- `last_sent_at`
- `last_replied_at`
- 是否存在成功发送记录
- 是否存在收到记录

失败发送日志不进入成功发送次数和已联系判断。

### 13.2 当前身份任务字段

以下信息继续只基于当前操作身份：

- 最新匹配分数。
- 准备中。
- 待发送。
- 首次草稿失败或发送失败。

### 13.3 状态优先级

首页状态按以下顺序派生：

```text
1. 共享范围存在 received 逻辑事件 -> replied
2. 共享范围存在成功 sent 逻辑事件 -> contacted
3. 当前身份最新有效任务失败 -> failed
4. 当前身份最新有效任务已批准或已排程 -> ready_to_send
5. 当前身份最新有效任务处于准备阶段 -> preparing
6. 其他 -> not_contacted
```

其他身份只有草稿、待审核、定时或失败任务，但尚未产生真实通信时，不改变当前身份下的准备类状态。

### 13.4 首页筛选和排序

现有基于状态、发送次数、最后发送时间和最后回复时间的筛选与排序自动使用共享聚合值。匹配度筛选和排序继续使用当前身份的匹配结果。

## 14. 统计面板口径

统计面板需要明确区分“共享通信数据”和“当前身份任务数据”。

### 14.1 共享通信数据

以下指标按共享范围计算：

- 发送数：成功 `sent` 逻辑事件数。
- 已联系导师数：至少有一条成功 `sent` 或 `received` 事件的去重导师数。
- 已回复导师数：至少有一条 `received` 事件的去重导师数。
- 回复率：已回复导师数 / 已联系导师数。
- 发送趋势：按 `sent` 事件时间统计。
- 回复趋势：按 `received` 事件时间统计。

日期、学校和学院筛选继续应用于共享通信事件关联的导师。

### 14.2 当前身份任务数据

以下指标继续按当前身份计算：

- 发送失败数。
- 发送失败率。
- 待审核数。
- 已排程数。
- 任务漏斗。
- 任务状态分布。
- 待跟进列表。

发送失败率的分母必须使用当前身份成功发送数加当前身份失败数，不能使用共享组总发送数。

### 14.3 导师分析区域

“高匹配未联系”使用：

- 当前身份的匹配分数。
- 共享范围的联系状态。

因此组内任一身份已经联系该导师后，该导师不再出现在其他组成员的“高匹配未联系”列表中。

### 14.4 UI 标识

- 真实发送、回复和趋势区域标记“共享通信”。
- 待审核、定时、失败、漏斗和跟进区域标记“当前身份”。
- 未分组身份不需要额外强调，因为两种范围相同。

## 15. 任务中心行为

- 任务列表继续按当前 `identity_id` 查询。
- 批次的总数、成功数、失败数、回复数继续只统计该批次自己的任务。
- 批次和任务操作不扩展到共享成员。
- 从任务中心打开某任务时，以该任务的 `identity_id` 作为当前操作身份。
- 打开后的工作区时间线按该身份所属共享组合并。
- 共享组内其他身份收到回复，不跨身份修改当前任务状态。

## 16. API 设计

### 16.1 共享组 DTO

```text
IdentityCommunicationGroupRead
- id
- members: IdentityCommunicationGroupMemberRead[]
- created_at
- updated_at

IdentityCommunicationGroupMemberRead
- id
- profile_name
- email_address
- is_default
```

身份列表 DTO 增加：

- `communication_group_id: int | null`

前端已经持有完整身份列表，可以据此计算当前身份的成员集合和稳定 scope key，无需在每个身份 DTO 中重复返回成员数组。

### 16.2 接口

- `GET /api/communication-groups`
  - 返回全部共享组及成员。
- `POST /api/communication-groups`
  - 创建共享组。
  - payload：`identity_ids`、`confirm_merge_existing_groups`。
- `PUT /api/communication-groups/{group_id}`
  - 原子替换组成员。
  - payload：`identity_ids`、`confirm_merge_existing_groups`。
- `DELETE /api/communication-groups/{group_id}`
  - 解散共享组。

### 16.3 校验和错误

- 少于两个身份：`422`。
- 身份不存在：`422`，返回无效 ID。
- 身份 ID 重复：后端规范化去重；去重后少于两个仍返回 `422`。
- 组不存在：`404`。
- 成员属于其他组且未确认合并：`409`，返回冲突组和成员摘要。
- 确认合并后：在同一事务内移动所有成员、删除空组并记录操作日志。
- 数据库写入失败：事务整体回滚，不允许部分成员更新。

### 16.4 现有接口兼容

工作区、首页和统计接口继续接收单个 `identity_id`。前端不向这些接口传组 ID 或成员 ID 列表。

服务端根据 `identity_id` 解析共享范围，使任务动作返回、后台逻辑和未来调用方都得到相同结果。

## 17. 前端状态与缓存失效

当前全局选择状态继续维护：

- `selectedIdentityId`
- `selectedIdentity`

新增派生值：

- `communicationIdentityIds`
- `communicationScopeKey`

`communicationScopeKey` 使用排序后的成员 ID 生成，例如 `1:2:5`。它只用于请求失效和 UI 展示，不作为后端授权数据。

请求 key 调整：

- 首页导师列表：当前身份 ID + `communicationScopeKey`。
- 工作区：导师 ID + 当前身份 ID + 模型 ID + `communicationScopeKey`。
- 统计面板：当前身份 ID + 模型 ID + `communicationScopeKey` + 现有筛选条件。
- 任务中心：保持当前身份 ID，不加入 scope key。

共享组创建、编辑或解散成功后：

1. 刷新身份与共享组列表。
2. 重新计算 scope key。
3. KeepAlive 中的首页、工作区和统计面板立即失效并重新请求。
4. 任务中心不因共享组变化重新解释已有任务。

不能依赖用户刷新页面才能看到成员变化。

## 18. 个人中心交互

个人中心身份管理区域新增“通信记录共享”区。

### 18.1 未分组状态

- 展示当前未分组身份。
- 提供“创建共享组”操作。
- 创建时使用复选框选择至少两个身份。
- 提交前明确说明：只共享通信记录和通信统计，不共享发件配置、材料或任务。

### 18.2 已分组状态

- 每组展示成员身份名称和邮箱。
- 提供“编辑成员”和“解散共享组”。
- 编辑时可添加未分组身份或移除现有成员。
- 选中另一个组的成员时显示合并确认，列出两个组的全部成员。
- 解散前说明不会删除任何身份或通信数据。

### 18.3 保存反馈

- 保存中禁止重复提交。
- 保存失败保留当前选择，不关闭编辑界面。
- 合并冲突使用明确确认流程，不自动重试为合并。
- 保存成功后刷新全局上下文并通知受影响页面重新加载。

## 19. 操作日志与诊断

记录以下操作日志：

- `communication_group.created`
- `communication_group.updated`
- `communication_group.merged`
- `communication_group.deleted`

元数据至少包含：

- 变更前成员 ID。
- 变更后成员 ID。
- 被合并组 ID。
- 触发操作的当前身份 ID，如有。

普通读取和共享范围解析不写操作日志。

手动刷新部分失败时，诊断日志保留每个身份原有的 IMAP 错误上下文，不用共享组错误覆盖底层身份错误。

## 20. 性能要求

- 共享范围解析最多使用一次成员查询，不允许逐身份 N+1。
- 工作区真实消息使用单次 `identity_id IN (...)` 查询，不由前端分别请求每个身份。
- 首页状态使用集合查询和按导师聚合，不逐导师、逐身份查询。
- 统计面板使用集合查询后统一聚合。
- 第一版沿用工作区完整时间线加载，不新增分页。
- 现有 `email_logs` 复合索引优先用于 `identity_id IN + professor_id + direction` 查询。
- 实现阶段必须用 SQLite 实际查询计划验证共享查询；只有确认现有索引不足时才新增索引。
- 至少覆盖 10 个共享身份、1000 位导师和 10000 条通信记录的服务层性能回归，避免算法按身份数乘导师数增长。

## 21. 数据迁移与兼容

Alembic 迁移只执行本地结构变更：

1. 创建 `identity_communication_groups`。
2. 为 `identity_profiles` 增加可空 `communication_group_id`。
3. 创建外键和索引。
4. 所有现有身份保持 `NULL`，无需回填组。

迁移不得：

- 修改现有 `EmailLog.identity_id`。
- 修改现有 `EmailTask.identity_id`。
- 复制通信记录。
- 调用 IMAP 或其他网络服务。
- 自动推断哪些身份应该共享。

升级后所有现有用户默认保持单身份视图。只有用户主动创建共享组后才改变展示。

## 22. 错误和边界场景

- 共享组成员缺少 IMAP 配置：仍展示已有本地记录，手动刷新时跳过或返回身份级警告。
- 某成员 IMAP 失败：其他成员成功同步的记录正常展示。
- 身份邮箱配置变更：共享关系不变，现有通信归属不变。
- 身份改名：所有来源标签使用最新 `profile_name`。
- 两个身份名称相同：来源标签追加邮箱。
- 同一邮件被多个身份同步：时间线和统计折叠，来源身份合并。
- 同一主题和正文由不同身份分别发送，但 Message-ID 不同：保留为两条记录。
- 当前身份没有任务但组内有历史：展示历史，不借用其他身份任务作为当前任务。
- 当前身份新建草稿：其他成员看得到的真实历史不进入草稿保存内容。
- 成员被移出组：记录不删除，但其他成员立即不再看到该身份记录。
- 组被解散：各身份恢复独立视图。
- 身份被删除：沿用现有级联删除行为，并可能使共享历史减少。
- 数据库中出现空组或单成员组：读取时不扩大范围；后台维护或下次编辑时清理。

## 23. 测试计划

### 23.1 后端共享组

- 创建两个身份的共享组成功。
- 少于两个身份被拒绝。
- 不存在的身份被拒绝。
- 同一身份不能静默加入两个组。
- 未确认时跨组添加返回 `409`。
- 确认后两个组原子合并。
- 编辑成员后新增和移除立即生效。
- 解散组只清空关联，不删除身份、任务和通信记录。
- 删除成员导致只剩一个成员时自动解散。
- 操作日志记录成员变更前后值。

### 23.2 共享范围解析

- 未分组身份只返回自身。
- 组内任一成员返回相同成员集合。
- 当前身份始终排在第一位。
- 不存在身份返回现有错误。
- 异常空组或单成员组回退到自身。

### 23.3 工作区

- A、B 同组，C 不同组；A 工作区包含 A、B 消息，不包含 C。
- 切换到 B 后消息集合相同，当前任务切换为 B。
- A 当前任务草稿可见，B 和 C 草稿不可见。
- A 没有任务但 B 有真实历史时仍返回历史。
- 所有 thread 动作接口返回相同共享消息范围。
- 消息按跨身份时间稳定排序。
- 同 Message-ID 的 A、B 记录折叠为一条并返回两个来源身份。
- 不同 Message-ID 的相同正文保留两条。
- 来源身份重名时 DTO 信息足以由前端区分。

### 23.4 首页状态

- B 已发送、A 无任务，选择 A 时显示 `contacted`。
- B 已回复、A 有失败任务，选择 A 时显示 `replied`。
- B 只有待审核任务、A 无任务，选择 A 时显示 `not_contacted`。
- A 有待审核任务、B 无通信，选择 A 时显示 `preparing`。
- `sent_count` 对跨身份重复邮件只计一次。
- 最后发送和回复时间取共享范围内最大值。
- 匹配分数仍取 A 的任务，不使用 B。

### 23.5 统计面板

- 发送、联系、回复和趋势聚合 A、B，排除 C。
- 跨身份重复记录不重复统计。
- 待审核、定时、失败和任务漏斗只统计 A。
- 发送失败率使用 A 的成功发送和失败数据，不使用共享总发送数。
- B 已联系导师后，该导师不出现在 A 的高匹配未联系列表。
- 日期和学校筛选作用于共享通信数据。

### 23.6 同步

- 手动刷新会尝试同步 A、B，不同步 C。
- A 成功、B 失败时返回 A 的新记录和 B 的警告。
- 缺少 IMAP 配置的成员不阻断其他成员。
- 现有身份级锁和限流仍生效。
- 重复刷新不产生重复逻辑通信事件。

### 23.7 前端

- 可以创建、编辑、合并和解散共享组。
- 顶部身份选择器保持单选。
- 工作区显示共享范围标识和消息来源身份。
- 切换同组身份会重新加载任务和草稿。
- 共享组保存后首页、工作区和统计立即刷新。
- 任务中心不因 scope key 变化混入其他身份任务。
- 保存失败保留用户已选成员。
- 删除身份确认说明共享历史影响。

### 23.8 迁移

- 旧数据库升级后所有身份保持未分组。
- 升级不修改现有任务和日志数量、归属或唯一键。
- 新建、编辑和删除身份仍正常工作。
- 数据库备份与恢复流程包含新表和外键。

## 24. 验收场景

### 场景一：合并查看

1. 用户创建身份 A、B、C。
2. 用户把 A、B 加入同一共享组，C 保持独立。
3. B 曾给导师 X 发信并收到回复。
4. 用户选择 A。
5. 首页中导师 X 显示已回复，并展示共享发送次数和最后回复时间。
6. 工作区展示 B 的发送与回复记录，每条记录标明 B。
7. C 的任何记录不出现。

### 场景二：保持发送归属

1. 用户仍选择 A。
2. 工作区展示 A、B 合并历史。
3. 用户新建或发送邮件。
4. 草稿使用 A 的模板与材料，邮件通过 A 的 SMTP 发出。
5. 新 `EmailTask`、`EmailLog` 继续关联 A。
6. B 的任务和发送限额不受影响。

### 场景三：同组切换

1. 用户从 A 切换到 B。
2. 合并通信时间线内容保持一致。
3. 当前任务、草稿、材料和发件设置切换为 B。
4. 未保存草稿保护正常生效。

### 场景四：移出共享组

1. 用户把 B 从 A、B 共享组移出。
2. 共享组因只剩 A 自动解散。
3. A、B 的历史记录不被删除。
4. 选择 A 时只看到 A 的记录，选择 B 时只看到 B 的记录。

### 场景五：旧用户兼容

1. 旧数据库升级到新版本。
2. 用户不创建共享组。
3. 首页、工作区、统计和任务中心行为与升级前一致。

## 26. 已确认决策

本规格采用以下已确认产品决策：

1. 第一版只合并展示，不阻止组内不同身份重复联系同一导师。
2. 当前任务、草稿、材料和发送动作永远只属于当前操作身份。
3. 首页真实联系状态按共享组计算，准备类状态只按当前身份计算。
4. 统计面板同时存在“共享通信”和“当前身份任务”两种明确标识的口径。
5. 跨身份同一物理邮件必须折叠，并保留全部来源身份。
6. 第一版共享组无自定义名称，使用成员身份生成摘要。
7. 删除身份沿用现有级联语义，可能删除共享视图中的历史记录。
