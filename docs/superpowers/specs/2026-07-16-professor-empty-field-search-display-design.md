# 导师空字段搜索与列表显示设计

## 背景

PR #75 为首页和导师管理页增加了空字段搜索：用户在关键词搜索框中输入精确关键词 `无`，即可匹配所选范围内值为 `null`、空字符串或纯空白的字段。

当前两个列表对空字段的显示并不统一。部分字段显示“未填写邮箱”“未填写研究方向”等长文案，空标签则不显示占位文案。为了让用户从列表内容自然理解 `无` 可以用于搜索空字段，本设计将当前已经显示的空字段文案统一为 `无`，同时保持列表结构和空标签行为不变。

PR #75 在首页和导师管理页的过滤模块中分别维护了一份相同的空字段匹配 helper。本设计同时将该逻辑抽取为共享实现，避免两个页面后续出现行为差异。

## 目标

- 首页和导师管理页中，当前已经显示的字段在整格为空时统一显示 `无`。
- `null`、空字符串和纯空白使用相同的空值判断。
- 页面显示与关键词 `无` 的过滤语义使用同一份共享空值逻辑。
- 首页和导师管理页共用同一份空字段搜索 helper。
- 保持普通关键词的包含搜索、多范围 OR 语义和高级筛选行为不变。
- 保持空标签当前的视觉行为，不显示 `无`。

## 非目标

- 不新增列表字段或表格列。
- 不在列表中新增“系所”展示。
- 不为组合字段中缺失的单个字段补 `无`。
- 不调整标签样式、标签添加按钮或空标签状态。
- 不修改编辑表单、详情页、工作区侧栏或其他页面的空值文案。
- 不修改数据库、API 数据结构或导师数据。
- 不把用于展示的 `无` 写入表单或发送给后端。

## 显示规则

### 通用空值规则

以下值视为空字段：

- `null`
- `undefined`
- 空字符串 `""`
- 去除前后空格后为空的字符串

非空字符串显示去除前后空格后的内容。`无` 仅是前端展示文案和专用搜索关键词，不是数据值。

### 首页导师列表

首页继续使用现有列表结构，不新增字段。

- 姓名：必填字段，保持现有显示。
- 标签：有标签时保持现有标签；无标签时仍只保留现有添加标签按钮，不显示 `无`。
- `职称 / 学校 / 学院` 摘要：先忽略其中的空字段并拼接已有内容；只有整段摘要为空时显示 `无`。
- 研究方向：为空时显示 `无`。

示例：

| 职称 | 学校 | 学院 | 列表摘要 |
| --- | --- | --- | --- |
| 教授 | MIT | 计算机学院 | `教授 / MIT / 计算机学院` |
| 空 | MIT | 计算机学院 | `MIT / 计算机学院` |
| 空 | 空 | 计算机学院 | `计算机学院` |
| 空 | 空 | 空 | `无` |

### 导师管理列表

导师管理页继续使用现有列结构。

- 姓名：必填字段，保持现有显示。
- 标签：有标签时保持现有标签；无标签时不显示 `无`。
- 职称：整格为空时显示 `无`。
- 邮箱：整格为空时显示 `无`。
- `学校 / 学院`：先忽略其中的空字段并拼接已有内容；只有整格为空时显示 `无`。
- 研究方向：整格为空时显示 `无`。
- 更新时间：不属于关键词搜索空字段范围，保持现有显示。

## 共享空字段模块

新增共享模块：

```text
frontend/src/lib/professorSearchField.ts
```

该模块负责以下职责：

- 定义专用空字段关键词和显示文案 `无`。
- 归一化搜索文本：去除前后空格并转为小写。
- 判断导师搜索字段是否为空。
- 判断字段是否匹配已经归一化的关键词。
- 把单个搜索字段格式化为列表显示值，空值返回 `无`。

建议导出接口：

```ts
export const EMPTY_PROFESSOR_FIELD_VALUE = "无";

export const normalizeProfessorSearchText = (
  value: string | null | undefined,
): string;

export const isProfessorSearchFieldEmpty = (
  value: string | null | undefined,
): boolean;

export const matchesProfessorSearchField = (
  value: string | null | undefined,
  normalizedKeyword: string,
): boolean;

export const formatProfessorSearchField = (
  value: string | null | undefined,
): string;
```

`matchesProfessorSearchField` 的规则：

- 关键词精确等于 `无`：仅匹配空字段。
- 其他关键词：继续使用归一化后的包含匹配。

`formatProfessorSearchField` 的规则：

- 空字段：返回 `无`。
- 非空字段：返回去除前后空格后的原始文本，不进行小写转换。

组合字段继续由行组件负责拼接。组件先删除空成员并拼接已有内容，再使用 `formatProfessorSearchField` 处理整个拼接结果。这样只有整格为空时才显示 `无`。

## 组件调整

### 过滤模块

以下两个模块移除各自重复的 `normalize`、空字段常量和 `matchesKeywordValue`，改为使用共享模块：

- `frontend/src/features/home-dashboard/client/filterDashboardProfessors.ts`
- `frontend/src/features/professor-management/client/filterManagementProfessors.ts`

字段映射、搜索范围归一化、`some()` 实现的多范围 OR 语义，以及高级筛选逻辑保持不变。

### `DashboardProfessorRow`

- 组合摘要拼接时忽略 `null`、空字符串和纯空白。
- 组合摘要为空时显示 `无`。
- 研究方向通过共享格式化函数显示，空值显示 `无`。
- 不向 `ProfessorTagChips` 增加空值文案，不改变无标签行为。

### `ManagementProfessorRow`

- 职称先沿用 `normalizeProfessorTitleDisplay`，再通过共享格式化函数显示。
- 邮箱和研究方向通过共享格式化函数显示。
- 学校和学院拼接时忽略 `null`、空字符串和纯空白，组合结果为空时显示 `无`。
- 不向 `ProfessorTagChips` 增加空值文案，不改变无标签行为。

## 数据流

搜索流程：

1. 页面把用户输入和所选搜索范围传给现有过滤函数。
2. 过滤函数使用共享模块归一化关键词。
3. 每个所选字段通过共享匹配函数判断。
4. 多个搜索范围继续通过 `some()` 组合为 OR 关系。
5. 关键词结果继续与高级筛选条件使用 AND 关系组合。

显示流程：

1. API DTO 保持原始的可空字段值。
2. 行组件仅在渲染时调用共享空值判断或格式化函数。
3. 空字段显示为 `无`，非空字段显示清理后的原始文本。
4. 不修改 DTO、页面状态或后端数据。

## 测试策略

### 共享模块

- `null`、`undefined`、空字符串和纯空白被识别为空。
- 非空字符串不被识别为空。
- 精确关键词 `无` 仅匹配空字段。
- ` 无 ` 经过关键词归一化后具有相同行为。
- `无人机` 继续匹配“无人机系统”。
- `无` 不匹配“无人机系统”或字段值本身为“无”的非空内容。
- 显示格式化对空字段返回 `无`，对非空字段返回去除前后空格后的原始文本。

### 过滤回归

- 保留 PR #75 对首页和导师管理页空字段搜索的测试。
- 保留普通关键词、搜索范围、多范围 OR 和高级筛选测试。
- 两个过滤模块通过共享 helper 后，原有测试结果不变。

### 首页行组件

- 职称、学校和学院全部为空时，组合摘要显示 `无`。
- 组合字段存在任一非空值时，只显示已有内容，不补 `无`。
- 研究方向为 `null`、空字符串或纯空白时显示 `无`。
- 无标签时不显示额外的 `无`，添加标签按钮仍可用。

### 导师管理行组件

- 职称、邮箱和研究方向为空时各自显示 `无`。
- 学校和学院都为空时显示 `无`。
- 学校或学院只有一个有值时，只显示已有内容，不补 `无`。
- 无标签时不显示额外的 `无`，添加标签按钮仍可用。
- 行选择、编辑、删除、恢复和标签操作行为不回归。

## 验收标准

- 首页当前已经显示的组合摘要和研究方向在整格为空时显示 `无`。
- 导师管理页当前已经显示的职称、邮箱、学校/学院和研究方向在整格为空时显示 `无`。
- 组合字段部分缺失时不补 `无`，只显示已有内容。
- 首页和导师管理页无标签时不显示 `无`。
- `null`、空字符串和纯空白的搜索与显示语义一致。
- 首页和导师管理页使用同一份空字段搜索 helper。
- 普通关键词搜索、多范围 OR、高级筛选及列表操作没有回归。
- 其他页面、表单、API 和数据库不受影响。
