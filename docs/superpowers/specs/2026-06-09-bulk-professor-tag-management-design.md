# 批量管理导师标签设计

## 背景

首页导师看板和导师管理页都已经支持多选导师，并在选中后显示底部 sticky 批量操作框。当前导师标签只能逐个导师编辑，批量整理导师标签时需要重复打开单个标签弹窗，效率低。

本设计新增“批量改标签”能力，让用户在首页或导师管理页选中多位导师后，一次性追加、移除或覆盖标签。

## 目标

- 在首页和导师管理页的已选中批量操作框中增加“批量改标签”入口。
- 支持三种批量语义：追加标签、移除标签、覆盖标签。
- 使用后端批量接口一次性完成更新，避免前端循环调用单导师接口。
- 成功后刷新当前页面中已选导师的标签展示，并保留当前选择。
- 复用现有导师标签选择、新建标签和通知体验。

## 非目标

- 不新增标签重命名、排序或删除能力。
- 不改变现有单导师标签编辑行为。
- 不把批量操作扩展到跨筛选条件的“全库命中结果”；本次只作用于用户已经选中的导师 ID。
- 不改变首页和导师管理页现有筛选、分页、多选规则。

## 用户体验

### 批量入口

当 `selectedIds.size > 0` 时，首页和导师管理页现有底部 sticky 批量操作框中新增按钮：

```text
批量改标签
```

按钮样式使用现有 `ui-btn-secondary`，图标使用 `Tags` 或 `Tag`。按钮位置放在“清空选择”之后、页面主批量动作之前。

首页操作顺序：

```text
清空选择 | 批量改标签 | 批量分析匹配度 | 创建批量任务
```

导师管理页操作顺序：

```text
清空选择 | 批量改标签 | 批量删除/恢复
```

### 批量弹窗

点击“批量改标签”打开“批量修改导师标签”弹窗。弹窗显示：

- 标题：`批量修改导师标签`
- 说明：`将应用到 N 位导师`
- 模式切换：`追加标签`、`移除标签`、`覆盖标签`
- 标签候选区：复用现有标签 chip 选择交互
- 新增标签区：复用现有“新增标签”交互
- 操作按钮：`取消` 和随模式变化的保存按钮

默认模式为 `追加标签`，因为它最不容易误伤已有标签整理结果。

保存按钮文案：

- 追加模式：`追加标签`
- 移除模式：`移除标签`
- 覆盖模式：`覆盖标签`

### 三种模式语义

- 追加标签：给所有选中导师增加弹窗中选中的标签，保留他们已有的其他标签。
- 移除标签：从所有选中导师中移除弹窗中选中的标签，保留其他标签。
- 覆盖标签：把所有选中导师的标签替换为弹窗中选中的标签；允许不选标签，用于清空选中导师的全部标签。

## 前端设计

新增共享组件 `BulkProfessorTagDialog`，由首页和导师管理页复用。它负责：

- 管理当前批量模式。
- 展示标签候选和新增标签表单。
- 维护用户选中的 `tagIds`。
- 在保存时回调父页面提交。

父页面负责：

- 控制弹窗开关。
- 提供 `professorTags` 候选。
- 调用新建标签 API。
- 调用批量更新标签 API。
- 用返回结果更新当前 `professors` 列表中的 `tags` 字段。
- 显示成功或失败通知。

现有 `ProfessorTagAssignmentDialog` 保持用于单导师编辑，不强行改造成兼容所有批量模式，避免让单个弹窗承担过多职责。

## 后端接口

新增接口：

```http
POST /api/professors/bulk-tags
```

请求体：

```json
{
  "professor_ids": [1, 2, 3],
  "mode": "add",
  "tag_ids": [10, 11]
}
```

`mode` 支持：

- `add`
- `remove`
- `replace`

校验规则：

- `professor_ids` 必须非空。
- `mode` 必须为 `add`、`remove` 或 `replace`。
- `add` 和 `remove` 模式下 `tag_ids` 必须非空。
- `replace` 模式下 `tag_ids` 可以为空，表示清空所有选中导师的标签。
- 如果任一导师 ID 不存在，返回错误，不做部分更新。
- 如果任一标签 ID 不存在，返回错误，不做部分更新。

响应返回更新后的导师列表，至少包含 `id` 和 `tags`。为了复用现有前端类型，可以返回 `ProfessorManagementItemDTO[]` 或新增轻量结果 DTO；实现时优先选择最小变更且类型清晰的方案。

## 数据一致性

后端在单个事务中处理所有选中导师：

- 追加模式对每个导师做标签并集。
- 移除模式对每个导师做标签差集。
- 覆盖模式把每个导师标签集合替换为请求中的 `tag_ids`。

接口不做部分成功。任何校验失败或保存失败都回滚整批操作。

## 错误处理

前端提交期间禁用保存按钮并显示 loading。

错误提示：

- 未选择导师：不打开弹窗或提示“请先选择导师”。
- 追加/移除模式未选择标签：禁用保存按钮，或在保存时提示“请选择要追加/移除的标签”。
- 覆盖模式未选择标签：允许保存，但按钮文案仍为“覆盖标签”，确认这是清空标签语义。
- API 失败：保持弹窗打开，显示后端错误消息或通用“批量修改标签失败”。

成功提示：

```text
已更新 N 位导师的标签。
```

成功后关闭弹窗，保留当前选择，方便用户继续批量分析、创建任务、删除或恢复。

## 测试范围

后端测试：

- 追加标签会保留原有标签并增加新标签。
- 移除标签只删除指定标签。
- 覆盖标签会替换原标签。
- 覆盖为空数组会清空标签。
- 空导师列表、非法模式、追加/移除空标签、不存在导师、不存在标签会返回错误且不产生部分更新。

前端测试：

- 首页选中导师后显示“批量改标签”按钮。
- 导师管理页选中导师后显示“批量改标签”按钮。
- 弹窗默认处于追加模式。
- 三种模式会提交正确的 `mode` 和 `tag_ids`。
- 成功后当前列表中对应导师标签更新，并显示成功通知。
- 失败后弹窗保持打开，保存按钮恢复可用。

## 验收标准

- 用户可在首页和导师管理页对选中导师批量追加、移除、覆盖标签。
- 批量更新通过单个后端接口完成，不通过前端循环保存单个导师。
- 成功后无需刷新页面即可看到当前列表中导师标签变化。
- 覆盖模式可清空标签；追加和移除模式必须选择至少一个标签。
- 后端批量操作具备事务性，不出现部分导师已更新、部分导师未更新的状态。
