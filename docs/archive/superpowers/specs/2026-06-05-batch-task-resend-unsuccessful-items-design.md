# 批量任务未成功项重新发起规格

## 背景

Auto Email Sender 支持定时批量发送。定时任务错过全部发送窗口后，批量任务会进入 `expired`，未发出的邮件子任务会进入 `canceled`，并记录 `cancellation_reason = "schedule_expired"`，前端展示为「发送窗口已过期」。

当前用户如果想继续发送这些邮件，只能重新回到导师筛选流程，手动找回同一批老师、重新选择身份、模板和材料。对于「发送窗口过期」「发送失败」「任务中止后想重新安排时间」等场景，这个流程重复且容易漏选。

本规格定义一个从批量任务详情页重新发起未成功项的入口。用户可以在旧任务中默认全选未成功触达的老师，也可以自行勾选或取消勾选，然后跳转到创建批量任务页重新创建任务。

## 目标

- 在批量任务详情页提供「重新发起未成功项」入口。
- 默认选中原任务中未成功触达、且没有被用户单独移除的老师。
- 支持用户全选、清空选择、逐项勾选或取消勾选。
- 跳转到创建批量任务页时，自动切换到原任务身份。
- 创建页预填原任务的发信模式、模板、默认分析材料、随信附件和老师名单。
- 创建页不继承原任务的 LLM 配置，使用用户当前选择的 LLM 配置。
- 创建页不继承原任务的发送日期、时间窗口和每天发送数量，避免复制过期排程。
- 在进入创建页前和创建页顶部明确提醒用户：已带入原身份、模板和材料，仍可自行修改。

## 非目标

- 不在原批量任务内原地重试。
- 不新增「批量任务草稿」数据模型。
- 不自动创建新任务。
- 不复制旧任务的发送日期、时间窗口或每天发送数量。
- 不复制旧任务的 LLM 配置，也不自动切换用户当前 LLM 选择。
- 不复用旧邮件子任务的已生成草稿、已审核正文或发送日志。
- 不改变现有发送窗口过期、发送失败、中止任务和删除任务的状态语义。

## 术语

- **未成功项：** 原批量任务中尚未成功触达老师的邮件子任务。
- **成功触达：** 邮件子任务状态为 `sent` 或 `reply_detected`。
- **单独移除项：** 邮件子任务状态为 `canceled`，且 `cancellation_reason = "user_removed"`。
- **重发候选项：** 可被带入新批量任务的未成功项。
- **重发预填上下文：** 前端跳转创建页时携带的老师名单和原任务配置快照。

## 候选规则

后端提供统一候选判断，前端不自行拼装业务规则。

### 默认纳入

重发候选项应满足：

- 属于当前批量任务。
- 对应老师仍存在，且未被移入回收站。
- 邮件子任务不是成功触达状态。
- 邮件子任务不是单独移除项。

默认纳入的典型状态包括：

| 状态 | 取消原因 | 默认原因文案 |
| --- | --- | --- |
| `canceled` | `schedule_expired` | 发送窗口已过期 |
| `canceled` | `batch_stopped` | 任务中止后未发送 |
| `send_failed` | 无 | 发送失败 |
| `draft_failed` | 无 | 草稿生成失败 |
| `review_required` | 无 | 待审核未发送 |
| `approved` | 无 | 已批准未发送 |
| `scheduled` | 无 | 已排程未发送 |
| `discovered` / `matched` / `generating_draft` | 无 | 尚未完成发信准备 |

### 默认排除

以下项不进入重发候选：

- `sent`。
- `reply_detected`。
- `canceled + user_removed`。
- 老师已归档或不存在。

如果未来新增取消原因，后端应按保守策略处理：只要不是 `user_removed`，且未成功触达，就可以作为候选，但需要返回可读原因文案。

## 后端接口

新增接口：

```text
GET /api/batch-tasks/{task_id}/resend-context
```

接口职责：

- 校验批量任务存在。
- 加载任务身份、模板、材料配置和邮件子任务。
- 根据候选规则返回可重发项和默认选中项。
- 返回创建页需要预填的配置快照。
- 对不可用项返回原因，便于前端展示或统计。

建议响应结构：

```json
{
  "task": {
    "id": 12,
    "name": "批量任务 2026/6/5",
    "identity_id": 3,
    "schedule_type": "scheduled"
  },
  "defaults": {
    "identity_id": 3,
    "outreach_generation_mode": "llm",
    "outreach_template_subject": "申请与{{name}}老师交流科研方向",
    "outreach_template_body_text": "{{name}}老师您好，我希望申请加入您的课题组。",
    "outreach_template_body_html": "<p>{{name}}老师您好，我希望申请加入您的课题组。</p>",
    "primary_material_id": 10,
    "selected_material_ids": [11, 12]
  },
  "items": [
    {
      "email_task_id": 101,
      "professor_id": 88,
      "professor_name": "张三",
      "professor_email": "zhang@example.edu",
      "status": "canceled",
      "cancellation_reason": "schedule_expired",
      "reason_label": "发送窗口已过期",
      "default_selected": true,
      "selectable": true,
      "unavailable_reason": null
    }
  ],
  "summary": {
    "candidate_count": 8,
    "default_selected_count": 8,
    "unavailable_count": 0
  }
}
```

字段说明：

- `defaults.identity_id` 使用原任务身份。
- `defaults` 不包含 `llm_profile_id`。
- `defaults` 不包含 `scheduled_dates`、`window_start_time`、`window_end_time`、`emails_per_window`。
- `primary_material_id` 或 `selected_material_ids` 如果在当前身份下已不存在，应过滤掉，并在响应中提供提醒信息。
- `items.default_selected` 初始为 `true`，前端可以让用户取消勾选。
- `items.selectable = false` 用于展示被排除但值得说明的项，例如老师已归档。

创建新任务仍使用现有接口：

```text
POST /api/batch-tasks
```

后端 `createBatchTask` 继续执行最终校验，避免老师归档、材料删除、身份变更等并发变化绕过校验。

## 前端交互

### 任务详情页入口

在批量任务详情页增加操作按钮：

```text
重新发起未成功项
```

展示条件：

- 当前任务有至少 1 个可选择候选项。
- 当前任务不在回收站视图中。

按钮点击后打开选择面板。面板内容包括：

- 原任务名称。
- 候选统计，例如「可重新发起 8 位，已选 8 位」。
- 「全选可发起」「清空选择」按钮。
- 候选老师列表，支持逐项勾选。
- 每行展示老师姓名、邮箱、状态、原因文案和最近更新时间。

如果没有可选择候选项，入口可以隐藏；如果用户通过刷新或状态变化进入空结果，面板展示空状态：

```text
当前任务没有可重新发起的老师。
```

### 跳转前确认

用户点击「去创建新任务」时，如果已选数量大于 0，弹出确认框：

```text
确认重新发起这批老师？

将自动切换到原任务身份，并带入原任务使用的发信模式、模板和材料。模型使用当前已选择的模型，发送日期和时间窗口需要重新设置。进入创建页后仍可修改这些内容。
```

确认按钮：

```text
去创建新任务
```

取消按钮：

```text
继续选择
```

确认后前端执行：

1. 调用 `setSelectedIdentityId(originalIdentityId)`，切换到原任务身份。
2. 保持 `selectedLlmProfileId` 不变。
3. 将选中的 `professor_id` 写入现有 `sessionStorage` 键 `selected_professor_ids`。
4. 将重发预填上下文写入新的 `sessionStorage` 键，例如 `batch_resend_prefill_context`。
5. 跳转到 `/create-task`。

### 创建页预填

创建批量任务页启动时读取重发预填上下文。

如果上下文存在且身份匹配：

- 任务名称默认使用：`重新发起 - {原任务名称}`。
- 老师名单使用已选 `professor_id`。
- 发信模式使用原任务配置。
- 模板主题、纯文本正文和 HTML 正文使用原任务配置。
- 默认分析材料和随信附件使用原任务配置中仍可用的材料。
- 发送方式保持默认 `immediate`，或保留页面原默认值。
- 定时发送日期、开始时间、结束时间和每天发送数量不从原任务带入。
- LLM 配置使用当前全局选择。

创建页顶部展示提示：

```text
已从「{原任务名称}」带入 {N} 位老师、原身份、模板和材料。模型使用当前选择，发送时间需要重新设置；提交前可自行修改。
```

提示只影响当前创建流程。任务创建成功或用户离开创建页时，应清理重发预填上下文，避免污染下一次新建任务。

如果上下文身份与当前全局身份不一致，创建页应优先等待 `SelectionContext` 切换完成；如果切换失败或原身份不存在，展示错误提示并清理上下文。

## 数据流

1. 用户在任务中心打开批量任务详情。
2. 前端调用 `GET /api/batch-tasks/{task_id}/resend-context`。
3. 后端返回候选项和预填配置。
4. 前端默认勾选 `default_selected = true` 的候选项。
5. 用户调整勾选结果。
6. 用户确认跳转。
7. 前端切换到原任务身份，写入 `sessionStorage` 预填上下文，跳转创建页。
8. 创建页读取上下文，加载老师和当前身份材料，填充表单。
9. 用户重新选择发送方式和发送窗口。
10. 用户提交后调用现有 `POST /api/batch-tasks` 创建新批量任务。

## 边界处理

### 原身份不存在

如果原任务身份已删除，`resend-context` 应返回 400，错误文案：

```text
原任务身份已不存在，无法直接重新发起。
```

### 原材料不存在或不再可用

如果默认分析材料或随信附件已删除：

- 后端从 `defaults` 中过滤不可用材料。
- 响应中提供提醒，例如「部分原材料已不存在，未带入新任务」。
- 创建页仍允许继续创建。

如果默认分析材料不再支持作为分析材料，应不再带入 `primary_material_id`。

### 老师已归档或不存在

老师已归档或不存在时，不作为可选择候选项。选择面板可以展示为不可选，并说明：

```text
导师已归档，未带入新任务。
```

### 当前没有 LLM 配置

创建页沿用现有校验：没有身份或模型时不允许创建。由于本功能不切换 LLM 配置，如果用户当前没有可用模型，创建页展示现有「选择身份和模型」提示。

### 旧任务仍在运行

运行中的任务也可以打开候选选择面板，但只应纳入当前已经未成功触达且未成功发送的项。为避免重复发送风险，发送中 `sending` 状态不应默认可选。

如果需要第一版更保守，可以仅在 `expired`、`stopped`、`completed` 等不会继续自动推进的批量任务上展示入口。

本规格推荐第一版采用保守展示条件：仅对 `expired`、`stopped`、`completed` 任务展示入口；后续如有需要再扩展到 `running` 和 `paused`。

## 测试范围

后端测试覆盖：

- `schedule_expired` 子任务进入候选并默认选中。
- `batch_stopped` 子任务进入候选并默认选中。
- `send_failed` 子任务进入候选并默认选中。
- `draft_failed`、`review_required`、`approved`、`scheduled` 等未成功项进入候选。
- `sent` 和 `reply_detected` 不进入候选。
- `canceled + user_removed` 不进入候选。
- 老师已归档时不作为可选候选。
- 原材料不存在时从 `defaults` 过滤。
- 响应不返回 `llm_profile_id` 和旧排程字段。
- 原任务不存在或原身份不存在时返回明确错误。

前端测试覆盖：

- 任务详情页展示「重新发起未成功项」入口。
- 选择面板默认全选可发起候选项。
- 用户可以全选、清空选择、逐项勾选。
- 跳转前确认文案包含身份、模板、材料、当前模型和重新设置发送时间提示。
- 确认后调用 `setSelectedIdentityId` 切换到原任务身份，不调用 `setSelectedLlmProfileId`。
- 确认后写入 `selected_professor_ids` 和重发预填上下文。
- 创建页读取上下文后预填任务名称、发信模式、模板和材料。
- 创建页不预填旧排程。
- 创建成功后清理重发预填上下文。

## 验收标准

- 用户可以从批量任务详情页直接选择未成功触达老师并重新进入创建任务流程。
- 默认选择符合「未成功触达且未被单独移除」规则。
- 用户能清楚看到每个候选老师未成功的原因。
- 跳转前有明确确认，说明会切换到原身份、带入模板和材料、保留当前 LLM、需要重新设置发送时间。
- 创建页预填能减少重复配置，但用户仍可修改所有关键字段。
- 新任务通过现有创建接口生成，不复用旧邮件子任务状态和日志。
