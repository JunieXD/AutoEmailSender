# 导师标签交互与排序二期设计

## 背景

导师标签一期已经支持标签库、导师多标签关联、自定义标签、删除标签、列表展示、关键词匹配和高级筛选。手动测试后发现，一期实现只覆盖了基础能力，列表空间利用、折叠查看、删除模式和标签排序仍不符合实际使用预期。

二期目标是在不推翻一期数据和 API 的基础上，补齐更细的标签交互。

## 目标

- 首页标签与导师姓名同一行展示。
- 首页根据姓名占用空间显示前 2-3 个标签，剩余标签折叠为 `+N`。
- `+N` 支持悬浮和点击查看全部标签。
- 导师管理页只显示一个主标签，剩余标签折叠为 `+N`。
- 导师管理页可从 `+N` 弹层中选择主显示标签。
- 编辑导师页支持当前导师已选标签拖拽排序。
- 编辑导师页标签区域更醒目，删除入口进入独立删除模式。
- 删除标签前根据使用情况显示不同确认文案和受影响导师列表。

## 非目标

- 不支持全局候选标签排序。
- 不支持标签分组或权限控制。
- 不支持批量给导师排序标签。
- 不在首页通过 `+N` 弹层修改排序；首页只查看全部标签。
- 不把“暂无标签”保存为真实标签。

## 数据模型

采用“每个导师自己的标签排序”。

`professor_tag_links` 增加：

- `sort_order`

规则：

- 同一个导师的标签按 `sort_order` 升序返回。
- 创建或更新导师时，后端按 payload 中 `tag_ids` 的数组顺序写入 `sort_order`。
- 删除某个标签后，所有导师与该标签的关联被删除。导师如果没有剩余标签，前端展示“暂无标签”。
- 管理页点击某个标签设为主显示标签，本质是把该标签移动到该导师 `tag_ids` 第一位并保存。

不增加全局 `ProfessorTag.sort_order`。同一个标签在不同导师身上的展示优先级可以不同。

## API 设计

保留一期 `tag_ids: number[]` 形式，但数组顺序变为有意义：

- `POST /api/professors`
- `PATCH /api/professors/{professor_id}`

后端写入标签关联时：

- 第一个 id 的 `sort_order = 0`
- 第二个 id 的 `sort_order = 1`
- 依此类推

导师 DTO 中 `tags` 必须按该导师的 `sort_order` 返回。

删除标签确认需要知道影响范围。新增接口：

- `GET /api/professors/tags/{tag_id}/usage`

返回：

- `tag`
- `professors`
  - `id`
  - `name`
  - `email`
  - `university`
  - `school`

前端删除标签前先调用 usage 接口，用于生成确认文案和导师列表。

## 首页展示

标签放在导师姓名同一行，位于导师姓名右侧。

展示规则：

- 无标签：姓名后显示低强调“暂无标签”。
- 有标签：优先展示排序靠前的标签。
- 根据可用空间显示 2-3 个标签。
- 剩余标签显示 `+N` 胶囊。
- 不因为标签过多把整行撑成多行。
- `+N` 支持 hover 和 click 展开。

弹层规则：

- 弹层显示该导师所有标签。
- 标签按导师自己的排序展示。
- 首页弹层只用于查看，不支持点击改排序。
- 鼠标离开或点击外部关闭。

## 导师管理页展示

导师管理页空间更紧，只显示一个主标签：

- 无标签：显示“暂无标签”。
- 有标签：显示排序第一的标签。
- 多于一个标签：主标签后显示 `+N`。

`+N` 弹层：

- 显示该导师所有标签。
- 当前主显示标签有选中态。
- 点击其他标签时，把该标签设为主显示标签。
- 前端调用更新导师接口，只调整该导师的 `tag_ids` 顺序，不修改导师其他字段。
- 保存成功后刷新当前列表或局部更新该导师行。

## 编辑导师页

标签区域整体比一期更大：

- 标题：“导师标签”。
- 顶部显示已选标签数量或“暂无标签”。
- 已选标签区域使用较大的胶囊。
- 候选标签区域保留点击选中/取消选中。

拖拽排序：

- 仅当前导师已选标签支持拖拽排序。
- 拖拽后立即更新表单内 `tag_ids` 顺序。
- 保存导师时按当前顺序提交。
- 取消弹窗不保存排序变更。

自定义和删除入口：

- `+ 自定义标签` 保持为创建入口。
- 旁边新增“删除标签”按钮。
- 平时每个标签不显示垃圾桶。
- 点击“删除标签”进入删除模式。
- 删除模式下每个真实候选标签右侧显示垃圾桶。
- 垃圾桶从标签右端平滑入场。
- 再次点击“删除标签”退出删除模式。

删除确认：

- 未被导师使用：提示“是否要删除这个标签？”
- 已被导师使用：提示“是否要删除这个标签？下列导师该标签将删除”，并列出导师姓名。
- 确认后调用删除接口。
- 删除成功后从标签候选中移除，并从当前表单 `tag_ids` 中移除。

## 组件设计

- `ProfessorTagChips`
  - 支持 `maxVisible`。
  - 支持 `+N` 弹层。
  - 支持紧凑模式和管理页单标签模式。
  - 可选 `onTagClick`，用于管理页设置主显示标签。

- `ProfessorTagPopover`
  - 复用弹层组件。
  - 处理 hover、click、外部点击关闭。

- `ProfessorTagSelector`
  - 负责编辑页标签选择、自定义标签、删除模式。
  - 负责调用删除确认入口。

- `SortableSelectedTags`
  - 负责已选标签拖拽排序。
  - 输入 `selectedTags`，输出排序后的 `tag_ids`。

## 错误处理

- 更新主显示标签失败：恢复原排序并提示。
- 删除标签 usage 查询失败：阻止删除并提示“获取标签使用情况失败”。
- 删除标签失败：保留删除模式和候选列表，提示错误。
- 拖拽排序不影响后端，只有保存导师或管理页设置主标签时才持久化。
- 如果标签在弹层打开期间被删除，前端刷新后关闭弹层。

## 测试计划

后端：

- 标签关联保存 `sort_order`。
- 创建导师时按 `tag_ids` 顺序返回标签。
- 更新导师时可改变标签顺序。
- usage 接口返回使用该标签的导师。
- 删除标签后导师剩余标签顺序保持相对稳定。

前端：

- 首页标签与姓名同一行渲染。
- `+N` 可展开全部标签。
- 首页弹层点击标签不触发排序。
- 管理页只显示主标签和 `+N`。
- 管理页弹层点击标签会调用更新接口并置顶。
- 编辑页删除模式下才显示垃圾桶。
- 删除已使用标签时显示受影响导师列表。
- 已选标签拖拽后提交顺序变化。

## 实现边界

建议拆成四个实现批次：

1. 后端 `sort_order` 迁移、序列化排序和 usage API。
2. 标签弹层组件和首页同排展示。
3. 管理页单标签展示和点击置顶。
4. 编辑页放大样式、删除模式和拖拽排序。
