# 关键词搜索范围设计

## 背景

首页导师看板和导师管理页的关键词搜索当前会同时匹配多个字段。用户搜索单字或短词时，容易因为职称、学校、学院等字段命中而得到过宽的结果。例如搜索“副”时，姓名里带“副”的导师和职称为“副教授”的导师都会出现。

## 目标

- 在首页和导师管理页为关键词搜索增加可选搜索范围。
- 默认行为保持为搜索全部字段。
- 用户可以通过下拉多选指定关键词只匹配哪些字段。
- 当只选择“姓名”时，搜索“副”只匹配姓名字段，不匹配“副教授”等职称内容。

## 范围

本次只调整首页导师看板和导师管理页的客户端关键词筛选。不会修改后端接口、导师数据结构、导入导出逻辑或高级筛选字段含义。

## 搜索字段

首页导师看板支持以下字段：

- 姓名
- 学校
- 学院
- 系所
- 职称
- 研究方向

导师管理页支持以下字段：

- 姓名
- 邮箱
- 学校
- 学院
- 系所
- 职称
- 研究方向

## 交互设计

关键词搜索框旁增加一个“搜索范围”下拉多选按钮。

- 默认全选所有字段，按钮文案显示“全部字段”。
- 用户取消部分字段后，按钮文案显示“已选 N 项”。
- 下拉内容使用复选框列表展示字段。
- 为避免用户输入关键词后完全无结果，组件不允许取消到 0 个字段；当只剩最后一个字段时，再次点击该字段不改变选择。
- “重置”会恢复全部字段。

## 数据流

过滤状态增加 `keywordFields` 字段，保存当前选中的搜索字段。

- 首页 `DashboardFilterState` 增加首页可用字段数组。
- 导师管理页 `ProfessorManagementFilterState` 增加管理页可用字段数组。
- 读取旧 sessionStorage 时，如果没有 `keywordFields`，使用默认全选。
- 写入 sessionStorage 时包含 `keywordFields`。
- 筛选函数根据 `keywordFields` 从导师对象中取对应字段，再执行现有的大小写不敏感包含匹配。

## 组件设计

新增一个可复用的搜索范围多选组件，供首页和导师管理页使用。

组件职责：

- 接收可选字段列表、当前选中字段、切换回调。
- 渲染下拉按钮和复选框菜单。
- 处理空选择保护。
- 复用现有按钮、边框、阴影和紧凑布局风格。

首页会把该组件放在关键词输入框内部右侧或紧邻搜索框右侧，保持当前筛选栏一行布局。导师管理页会在现有搜索输入旁增加同样的控件。

## 错误处理

该功能不引入异步请求。异常场景主要是旧缓存或非法缓存值：

- 读取到未知字段时丢弃。
- 读取后没有任何合法字段时恢复默认全选。
- 筛选字段为空值时沿用现有逻辑，按空字符串处理，不影响页面渲染。

## 测试计划

- 首页过滤测试：默认全选时行为与现有搜索一致。
- 首页过滤测试：只选姓名搜索“副”不会命中职称“副教授”。
- 首页过滤测试：只选职称搜索“副”可以命中“副教授”。
- 导师管理页过滤测试：只选邮箱可以按邮箱命中。
- 导师管理页过滤测试：只选姓名时不会命中邮箱、职称、学校等字段。
- 状态读取测试：旧缓存缺少 `keywordFields` 时使用默认全选。
- UI 测试或组件测试：搜索范围下拉不允许取消到 0 个字段。

## 非目标

- 不实现高级搜索语法，例如 `姓名:副`。
- 不将关键词搜索范围移动到高级筛选面板。
- 不改变学校、学院、系所、职称等高级筛选的独立筛选逻辑。
